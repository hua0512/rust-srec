# Release Notes

## `unreleased`

## Before you upgrade

- **Removed settings:** The Bigo **Mint Integrity Token** setting has been removed because Bigo checks no longer need it. Updating automatically cleans it up from saved platform, template and streamer settings. See [Recording and recovery](#recording-and-recovery).
- **Bigo recordings:** Bigo rooms now record the original app stream by default. New recordings are FLV files (often HEVC instead of H.264 TS) and always use the Mesio engine, even if another engine is configured. A recording may also split into multiple files if BIGO changes stream quality mid-broadcast. Post-processing HEVC files (such as remuxing or converting) requires FFmpeg 6.1 or newer, and not all browsers can play them in the web player. To keep using the website stream, turn off **Record the original stream** in the Bigo platform settings. See [Recording](https://docs.srec.rs/en/platforms/bigo#recording).
- **Notification proxies:** Webhook, Telegram, Gotify and Discord notifications, as well as browser push, now use the app's **Default proxy** instead of the server's proxy environment variables. Unless your **Default proxy** is set to **System proxy**, this changes how they connect after updating. If you relied on `HTTP_PROXY` or `HTTPS_PROXY` to send notifications, set those channels to **System proxy** after updating (browser push always follows **Default proxy**, and email notifications still connect directly). See [Notification proxy](https://docs.srec.rs/en/concepts/notifications#proxy).
- **Upload proxies:** rclone and Baidu Netdisk upload steps now use the app's **Default proxy** instead of the server's proxy environment variables. If you relied on `HTTP_PROXY`, `HTTPS_PROXY`, `RCLONE_HTTP_PROXY`, rclone's `--http-proxy` flag or BaiduPCS-Go's own proxy setting, set those upload steps to **System proxy** after updating. With any other proxy setting, rclone ignores the environment variables, and steps that still configure `--http-proxy` or BaiduPCS-Go's proxy setting will fail until those old settings are removed. See [Upload proxy](https://docs.srec.rs/en/reference/processors#upload-proxy).
- **Desktop sign-in:** After updating, the desktop app opens without asking for a password. If other people use this computer, turn on **Require password sign-in** under **Desktop → Backend & Security**. See [New features](#new-features).

## New features

- **Batch detection for Bilibili and Twitch:** A new **Batch Detection** platform setting checks up to 100 Bilibili or Twitch streamers in a single request, cutting down individual checks for offline streamers and reducing rate-limit risk when monitoring many channels. It is off by default and can be set per template or streamer. As a trade-off, stream starts may be detected up to a quarter of a check interval later, and because batch requests do not use an account, expired logins are only noticed once a streamer goes live. Batch checks are shown in a distinct style in the streamer's check history. See [Batch detection](https://docs.srec.rs/en/platforms/#batch-detection).
- **Live notifications for Bigo:** Bigo streamers can now be monitored using BIGO's own live notifications. Enable **Batch Detection** in the Bigo platform settings and choose a signed-in BIGO account: rust-srec is notified within seconds when a streamer goes live and no longer polls offline streamers individually (apart from a full check at least every 10 minutes). Note that this account follows every Bigo streamer you monitor (visible to them) and should not be used in the BIGO app at the same time, as BIGO allows only one active session. Without notifications, Bigo falls back to polling (which can detect streams late or miss short ones), shown on streamer cards and in settings. If notifications stop arriving or the connection drops for more than 5 minutes, monitoring falls back to polling with a warning on the streamers page and optional alert notifications, and **Reconnect now** retries immediately. See [Live notifications](https://docs.srec.rs/en/platforms/bigo#live-notifications).
- **Original-quality Bigo recordings:** Bigo rooms now record the original app stream by default—typically 720p or 1080p HEVC instead of the website's 540p H.264—without needing an account. Multi-host rooms, password-protected rooms (the platform default password applies to all streamers) and rooms whose original stream cannot be recorded automatically fall back to the website stream. To record the website stream by default, turn off **Record the original stream**; putting HLS first in **Preferred Formats** also tries the website stream first and falls back to the original stream if that fails. See [Before you upgrade](#before-you-upgrade) and [Recording](https://docs.srec.rs/en/platforms/bigo#recording).
- **QR code login for Weibo:** Weibo accounts can now be added by scanning a QR code with the Weibo app instead of copying cookies from a browser. Accounts remain optional, so an expired or missing account never interrupts monitoring or recording. Weibo accounts are verified on first use each day and when you click **Validate**: QR-signed accounts renew themselves automatically if signed out (notifying you only if renewal fails or a fresh login is needed), whereas pasted cookies do not renew and send a **Credential invalid** notification when signed out. See [Weibo](https://docs.srec.rs/en/platforms/others#qr-code-login).
- **Alerts when a streamer's checks keep failing:** Notification channels can now subscribe to **Streamer checks failing** and **Streamer checks restored**. An alert (including the platform and latest error) is sent once when a streamer's checks or recordings fail repeatedly and rust-srec starts spacing out retries, followed by a recovery alert once checks succeed or recording resumes. This works across all platforms so outages or platform changes do not go unnoticed when you are away from the streamers page. See [Notification System](https://docs.srec.rs/en/concepts/notifications#priority).
- **Proxies for notification channels:** Webhook, Telegram, Gotify and Discord channels now have a **Proxy** setting so notifications can reach services blocked where the server runs (such as Telegram from mainland China). Channels follow **Default proxy** unless set to **Direct**, **System proxy** or a saved proxy, and changes apply immediately to new and test notifications without a restart. The **Proxies** page shows which channels use each saved proxy, and proxies in use cannot be deleted. Email channels always connect directly. See [Notification proxy](https://docs.srec.rs/en/concepts/notifications#proxy).
- **Proxies for uploads:** rclone and Baidu Netdisk upload steps now have a **Proxy** setting so uploads can reach cloud storage that is blocked or slow where the server runs. Steps follow **Default proxy** unless set to **Direct**, **System proxy** or a saved proxy in a job preset or workflow step. The **Proxies** page shows which job presets and pipelines use each saved proxy, and proxies in use cannot be deleted. Configuration backups also preserve each step's proxy. See [Upload proxy](https://docs.srec.rs/en/reference/processors#upload-proxy).
- **Desktop settings page:** The desktop app has a new **Desktop** settings page. It controls **Launch at login**, **Start minimized to tray**, **Close button hides to tray** and **Minimize to system tray**, and opens the **Recordings Folder**, **Data Folder** and **Logs Folder**. **Prevent system sleep while recording** keeps the computer awake while a recording is running (the display can still turn off), and **Confirm before quitting during recordings** asks before you quit or restart with recordings in progress.
- **Remote server mode for the desktop app:** The desktop app can now connect to an existing **Remote rust-srec server** instead of running the built-in backend. Enter its address under **Desktop → Backend & Security** and click **Test connection** before saving. If the server becomes unreachable, the sign-in screen offers **Switch to local backend**.
- **Password-free sign-in on the desktop app:** With the **Built-in local backend**, the desktop app signs you in automatically when it opens. To protect it with a password, turn on **Require password sign-in** under **Desktop → Backend & Security**; if you have not set a password yet, you are asked to choose one first, and from then on the app asks for it when it opens. See [Before you upgrade](#before-you-upgrade).

## Recording and recovery

- With **Batch Detection** enabled for Bilibili or Twitch, streamers spotted as live in a batch are now checked right away instead of waiting for their next scheduled poll, so recordings start sooner. If that check does not find the stream yet, it retries after each subsequent batch that still shows the streamer live.
- Fixed Twitch recordings skipping live or ending segments around low-latency previews or ad breaks.
- Fixed Mesio HLS recordings of fMP4 streams that switch between more than eight different initialisation segments (for example around inserted ads) skipping video after returning to an earlier one.
- Fixed Bigo checks failing with a login prompt before checking whether a room is live, and fixed silently restricted Bigo accounts reporting live rooms as offline and missing recordings. Live status is now checked publicly without an account, and accounts are only used when fetching the website stream. If Bigo restricts an account without signing it out so it reports active rooms as offline, rust-srec now detects this, pauses the account for 30 minutes and moves to the next account in a failover pool. See [Bigo](https://docs.srec.rs/en/platforms/bigo).
- Fixed Weibo user links (such as `https://weibo.com/u/{uid}`) failing every check with "Extraction failed" and no notification once an account's login lapsed. User pages are now checked as a guest without needing an account. An account is only used when Weibo rejects guest lookups; if that account has been signed out, QR-signed accounts renew themselves while other accounts are marked as needing a new login and send a **Credential invalid** notification. See [Weibo](https://docs.srec.rs/en/platforms/others#weibo).
- Weibo now also accepts `m.weibo.cn/u/{uid}`, `m.weibo.cn/profile/{uid}` and `weibo.com/{uid}` links, and shows the streamer's name and avatar while they are offline.
- Fixed recordings staying active indefinitely while recording nothing (leaving an empty file or no file at all) when an HLS stream keeps refreshing without delivering segments or an FLV server keeps the connection open without sending media. Such recordings now stop with a network error after 60 seconds without media for HLS, or 90 seconds for FLV. The FLV timeout can be adjusted via **Max Stall Duration** under **Advanced → Download** on the Mesio engine's FLV tab. See [Stalled streams](https://docs.srec.rs/en/concepts/mesio#stalled-streams).
- Fixed **Split file now** never finding a clean cut point on HLS streams that carry timed metadata or ad markers alongside the video and audio.
- Fixed FLV recordings losing their duration and stream details on broadcasts that send stream events before metadata, and prevented zero-byte FLV files and fragmented MP4 files with no audio or video from being left behind when a recording ends or splits before any media arrives.
- Fixed 1080p H.265 streams showing a height of `1088` instead of `1080`.
- An HLS segment that keeps failing is now skipped after 45 seconds of retries instead of stalling the recording for about two minutes (any retry already in flight finishes first, and rate-limit waits are not counted). This can be adjusted via **Segment Retry Deadline** under **Advanced → Segment downloads** on the Mesio engine's HLS tab; DASH recordings use the same 45-second limit.
- Fixed **End Stream On Danmu Close** having no effect when set on a template or streamer. Previously only the platform setting was used, so turning it off for a streamer did not stop danmu close events from ending the recording.
- Fixed **Min Segment Size** deleting valid parts mid-recording and leaving gaps. When a stream's resolution or codec changes, recording continues in a new file; on low-bitrate streams, a part between two changes can be smaller than the minimum (1 MiB by default) and was previously deleted along with its chat file. Parts ended by a resolution or codec change are now kept even if smaller than the minimum, while short parts from stops, reconnects or ad breaks are still cleaned up. See [Resource Limits](https://docs.srec.rs/en/reference/settings#resource-limits).
- Fixed FFmpeg and Streamlink recordings that failed before recording anything leaving an empty hidden `.srec-chunks-…` folder in the output folder. The folder is now removed unless it holds parts of a recording that can still be recovered.
- Fixed Mesio HLS and DASH recordings that stopped before their first segment being reported as "stream is empty" even when a download or processing error was the cause. The failure now shows the actual error.
- Reduced server memory usage during FLV recordings with **Loop Protection** enabled and on installations with a large history of **Danmu Statistics**.
- Setting **Frequent words to keep** under **Danmu Statistics** to `0` now disables word frequency counting and CJK word segmentation while keeping the rest of the session's chat summary (totals, activity timeline, top chatters and gifts).
- Fixed Huya **Record Danmu** failing to capture live chat, including on rooms with custom URLs or links with query parameters, and stopped sending your Twitch login token to video servers.
- Fixed negative bitrate values on some Douyin streams breaking bitrate filters, and fixed password-protected Twitcasting links entered without `https://` losing their password.

## Workflows and file processing

- Fixed a restart leaving jobs whose selected processor is no longer available stuck waiting in the queue when more than 10,000 jobs were pending. They are now marked as failed at startup regardless of backlog size.
- Fixed the **Max Uploads** setting having no effect. Previously rclone uploads were limited only by **Max IO Jobs** (taking slots from moves and copies) while Baidu Netdisk uploads were unlimited, so setting **Max Uploads** to 1 could still run multiple uploads at once. **Max Uploads** (default 3) now limits both rclone and Baidu Netdisk uploads without counting against **Max IO Jobs**, and Baidu Netdisk uploads still run one at a time. Raise the limit if you previously ran more than 3 uploads concurrently (lowering applies immediately; raising above the startup value requires a restart).
- Fixed a workflow step's own timeout not applying to **Execute** steps. Commands were still stopped at the global **Execute Timeout** (1 hour by default), causing longer-running steps to fail early. A step's timeout now overrides **Execute Timeout** for that step.
- Fixed a cancelled or timed-out Baidu Netdisk upload overlapping with the next upload before BaiduPCS-Go finished exiting, which could corrupt its local data. The next upload now waits for the previous process to exit and notes this in the log; signing in from the account card reports that BaiduPCS-Go is busy in the meantime.
- Fixed rclone and Baidu Netdisk uploads multiplying retries and stalling upload slots under rate limits. Previously, rclone retried each failed attempt internally up to 3 times with up to 10 per-request retries, and upload steps with workflow retries configured ran both the step's retries and the preset's own retries. Each rclone attempt now runs once with per-request retries capped at 3 (override with `--retries` or `--low-level-retries` in extra arguments), logs transfer errors as they occur, and stops further in-run retries immediately on rate-limit or quota errors. When a workflow step configures automatic retries under **Retries and timeout**, rclone and Baidu Netdisk steps now defer retries to the workflow step instead of holding upload slots during retry waits.
- Workflow steps with automatic retries remaining no longer send **Pipeline failed** notifications or show a failed upload alert in the top bar for intermediate failures; a failure notification is sent only once all attempts are spent or when a non-retryable error occurs. Non-retryable failures—such as invalid configuration, missing paths, revoked credentials or files permanently rejected by Baidu Netdisk—now fail immediately instead of wasting remaining retry attempts.
- Prevented deleting or renaming a job preset or workflow still used by a pipeline, which previously caused those pipelines to fail at runtime. Such changes are now blocked with a dialog listing every place it is used (with links to each). Importing a configuration in **Replace** mode also keeps omitted presets and workflows that imported pipelines still need, listing them as warnings.
- Prevented deleting a recording session on **Sessions** while it is still live or still has processing jobs waiting or running.

## Configuration

- Fixed on/off options in a template's platform override or a streamer's **Platform options** tab (such as **Batch Detection**, **Force Origin Quality** and **End Stream On Danmu Close**) always showing as on or off even when unset, making it unclear whether they followed the platform setting. Previously, once toggled there, the only way to follow the platform again was editing JSON. These options now offer **Inherit**, **On** and **Off**, where **Inherit** follows the template or platform setting. See [Configuration layers](https://docs.srec.rs/en/concepts/configuration#important-merge-rules).
- Fixed **Replace All** in **Import Configuration** under **Backup & Restore** leaving settings, **Accounts** and **Proxies** choices on **Platforms** omitted from the backup, which could block deleting old accounts or proxies.
- Updating the log filter in global settings or through **Import Configuration** now takes effect right away without restarting rust-srec.
- **Import Configuration** now rejects a backup with an invalid log filter or a streamer address without a host before changing anything, instead of saving settings that cannot work.
- Fixed the Mesio engine's **Decryption Key Cache TTL (ms)** setting having no effect. When set, it now takes precedence over **Key Cache TTL (ms)**.

## Notifications

- Fixed **Web Push** under **Browser Notifications** failing to subscribe, update priority or unsubscribe when `AUTH_DISABLED=true`.

## Authentication and API

- Fixed **API Keys** keeping old permissions or staying active for up to five seconds after **Change Password** or **Import Configuration** updated or disabled an account.

## Web interface

- Fixed clicking the channel link on a streamer's avatar sending the desktop app into Recovery Mode instead of opening the channel in your browser.
- The global settings page now warns when **Max Uploads**, **Max CPU Jobs** or **Max IO Jobs** is raised: lowering these limits applies right away, while raising one above the startup value requires a restart (previously noted only in the server log).
- Template cards now show how many streamers use each template under **Used by** with a direct link to those streamers. Deleting a template still in use now explains why it cannot be deleted and offers a **Show streamers** button instead of a raw server error.
- Fixed the web interface failing to recognise several server responses and showing a generic error or raw server message instead (the desktop app was not affected). Sessions without danmu statistics now say they are unavailable instead of showing a load error, expired streams refresh properly in the player, proxy and account conflicts show clear explanations and usage lists, cancelling a just-finished pipeline no longer errors, forced password changes redirect immediately, and server-unreachable sign-in errors are now translated.
- Fixed multi-entry fields (such as keyword filters, stream selection and email recipients) adding unfinished text when typing with a Chinese or Japanese input method. Pressing Enter to pick a candidate no longer adds uncommitted text like pinyin; Enter now adds an entry only after composition finishes.
- Fixed the streamer list jumping back to page 1 after saving a streamer, clicking the back arrow on its edit page or cancelling **Add a streamer**. It now returns to the page you left with your search, filters and sorting intact.
- Fixed the **Per page** picker disappearing from lists (such as streamers, pipeline jobs and job presets) once all items fit on a single page, leaving no way to switch back to a smaller page size. The picker now stays visible whenever a smaller page size would paginate the list again.
- Improved sorting on the streamers list and dashboard: by default, streamers within each state are now ordered by when they last went live (most recent first) instead of by priority, with states ordered Live → Error → Offline → Disabled so recently finished streamers are no longer buried below disabled or long-inactive ones. Live streamers on the dashboard follow the same live-time order, sorting by **State** now uses this order instead of alphabetical order, and sorting by name is now case-insensitive.
- Fixed the **Custom** date range on the sessions page leaving out the final day, which caused single-day selections to show almost nothing. The range now includes the entire end day, and picking only a start day shows that day's sessions.
- The navigation path at the top of session and other detail pages now displays a short ID (such as `#6c333b6b`) with the full ID shown on hover, instead of a long full ID with wrongly capitalised letters.
- Fixed several form fields not being linked to their labels (including password fields on sign-in and password-change pages, job preset ID and description, and streamer name). Clicking the label now focuses the field, screen readers announce its name and errors, and invalid entries are outlined in red.
- Fixed browsers and password managers mishandling password fields: changing your rust-srec password now prompts them to save the updated login properly, and password or token fields for other services (such as email, notifications, stream passwords and Baidu Netdisk sign-in) are no longer auto-filled with your rust-srec login.
- Fixed phones and tablets auto-capitalising or autocorrecting usernames on the sign-in page, which caused case-sensitive sign-ins to fail.
- Fixed the theme mode and sidebar options on the **Theme** settings page not working with a keyboard. They can now be reached with Tab and selected with Enter or Space, and screen readers announce the active selection.
- Fixed tall dialogs overflowing the bottom of small windows or phone screens and pushing action buttons out of reach. Dialogs now fit within the window height and scroll internally.
- Fixed durations showing English units such as "2h 5m" in the Chinese interface, including session and recording lengths, active download duration, server uptime on **System Health**, average job duration and file-operation stall duration.
- The web interface now uses less CPU when its browser tab is in the background during recordings and uploads: progress updates pause high-frequency redraws in background tabs and catch up immediately when you return.
- Fixed active download speed, size, segment and ratio numbers on a streamer's page jumping abruptly and pausing between updates. They now transition smoothly from one update to the next.
- Fixed the **Top Talkers**, **Top Words**, **Top Gifters** and **Top Gifts** charts in a session's **Danmu Statistics** rendering all bars in black (hard to read in dark mode); each chart now uses its own colour again.
- The **Engines** and **Proxies** settings pages now use the same list layout as the rest of the settings pages. Each engine shows a summary of its configuration with quick action buttons, **System proxy** has its own status card, and each proxy can be expanded to see which settings use it.
- Fixed the QR code login dialog staying open after a scan succeeded. It now closes automatically shortly after the account is saved.
- Saving changes on a platform, template or engine settings page now keeps you on that page instead of returning to the list, so you can keep adjusting other tabs or settings and click **Back** when finished.
- Updated the rust-srec logo and desktop icon across the web interface, desktop app and documentation, and switched the default theme preset to **Orange** (the previous neutral preset remains available as **Zinc** under **Theme → Theme Preset**).

## Deployment and desktop

- Reduced the server's memory use on Linux hosts where transparent hugepages are set to `always`. In a test recording five streams with danmu, the server used about 170 MiB instead of 330 MiB. It no longer uses hugepages for its own memory; FFmpeg, rclone and the other tools it starts are not affected. Set `MIMALLOC_ALLOW_THP=1` to restore the previous behaviour. See [Environment Variables](https://docs.srec.rs/en/reference/environment#backend-service).
- Fixed the desktop app staying in the system tray, with the database still locked, after you closed the window that reports a startup error. Closing that window now quits the app.
- Fixed the desktop app exiting without a message when another rust-srec instance is already using its database. It now opens a window that explains the problem.
- Fixed the desktop app failing to start when the path of its data folder contains `?` or `%`.
- Fixed double-clicking the tray icon showing the window and then hiding it again. A double-click now always brings the window to the front.
- The desktop app now remembers its window size, position and maximised state across restarts. If the display it was on is no longer connected, it opens centred at the default size.
- When the desktop app runs its built-in backend, **Output Folder** settings now have **Browse** and **Open folder** buttons, and the **Binary Path** and **FFmpeg Path** fields in the FFmpeg and Streamlink engine settings have a **Browse** button.
- Playable recordings in a session's **Media Timeline** now have an **Open in player** button in the desktop app, which opens the file in your default media player.
- The tray icon now shows a red dot while recording, and its tooltip and menu show how many recordings are running and their total speed. The tray menu also opens your recordings, logs and data folders and has a **Check for Updates** item.
- The **Desktop** settings page also has **External Tools**, which shows the FFmpeg, FFprobe and Streamlink versions the app found and warns when FFmpeg is older than 6.1, and **Updates**, which checks for a newer desktop release and lets you skip a version. With the built-in backend, the check connects through the **Default proxy** when it is a saved proxy; otherwise it uses the system proxy.
- Fixed errors in the background replacing the whole desktop window with the Recovery Mode screen. Once the interface is running, they now appear as notifications; the recovery screen is kept for startup failures and crashes of the interface itself.
- Fixed clicking the Dock icon on macOS not bringing back a window that was hidden to the tray.
