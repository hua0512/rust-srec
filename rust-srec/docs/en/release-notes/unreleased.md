# Release Notes

## `unreleased`

## New features

- **Session page**: recorded chat now plays over the video when you watch a recording, timed to the picture. A **Danmu settings** panel in the player hides message types, sets opacity, font size, speed and how much of the picture the chat covers, merges repeated messages, pauses a message under the mouse, shows where the chat is busiest above the progress bar, and blocks words or users. Settings are remembered, and large chat files load without freezing the page. See [Record chat](../guides/danmu.md#watch-a-recording-with-its-chat).
- **Player page**: live streams now show their chat over the picture as it arrives, with the same show/hide button and **Danmu settings**. Each player in the grid shows its own stream's chat, and a hidden chat is not downloaded. See [Watch a live stream with its chat](../guides/danmu.md#watch-a-live-stream-with-its-chat).
- **Twitch**: new **Allow H.265 (HEVC)** and **Allow AV1** platform settings let you record the higher qualities some channels stream only in those codecs. Both are off by default, so recordings stay H.264 unless you turn them on. See [Twitch](https://docs.srec.rs/en/platforms/twitch).

## Fixes

- **Presets**: opening a saved remux preset or workflow step that encodes with NVIDIA (NVENC) could switch its encoder preset to Medium, and the next save kept that change. The saved preset is now kept.
- **Presets**: the preset editor now names each processor and shows its icon the same way as the workflow editor and the job pages.
- **Presets**: after you undo your edits to a saved preset, **Save Changes** now goes away again. Before, it stayed for most processors as if something had changed.
- **Notifications**: the webhook channel's timeout now accepts at most 300 seconds, like the Gotify one. The server never waited longer than that, so a higher value had no effect.
- **Presets**: the example values shown in empty remux fields and in the preset ID field are now translated.
- **Workflows**: **Detach & Edit** on a preset step now always starts from the preset's saved settings. Before, a change made from the keyboard to the preset settings shown in the step, which look read-only, was copied into the step without notice.
- **Streamers page**: a streamer whose saved settings could not be read, or held a value the recorder accepts, no longer stops the whole streamers list from loading. Such values include an extractor name in different capitalization or one the recorder does not know, an offline check count of 0 or a delay under one second, a retry policy with only some values set, a stream selection that has no format list saved, or a workflow step with an empty retry or timeout, for example from an imported configuration. Values the recorder accepts show as it applies them; settings that could not be read show as not configured.
- **Platforms, templates and global settings**: an extractor name in different capitalization or one the recorder does not know no longer stops the platforms or templates list or the global settings page from loading. A download retry policy with only some values set, a stream selection that has no format list saved, or a workflow step with an empty retry or timeout no longer shows as not configured on platforms and templates, and is no longer removed by the next save. A retry value that was left out shows the default the recorder uses.
- **Platforms and templates**: the **Stream lookup** setting now shows the saved choice, and saving any other change on the page no longer resets **Always use Streamlink** to the default.
- **Security**: a link crafted by another site could make the stream proxy show a page that acted as the signed-in user. The proxy now only passes on video, audio, images and playlists, and refuses requests from other sites.
- **Security**: a failed sign-in no longer writes the entered password to the server log, and a failed sign-out no longer writes the sign-in token.
- **Security**: a page on another port or subdomain of the same address could make the web interface carry out actions as the signed-in user. The web interface now refuses such requests. If it is behind a reverse proxy that changes the address the browser used and every action now fails with "Request refused", forward the original address or list it in `CSRF_TRUSTED_ORIGINS` (see [Environment variables](https://docs.srec.rs/en/reference/environment)).
- **Security**: an ID such as `..` sent to the web interface could make it reach a different server action than the one requested. Such IDs are now refused.
- **Security**: a recorded file opened straight from the server, such as a chat XML file, can no longer run scripts as the web interface.
- **Security**: when a stream is played with a platform account, more kinds of platform error pages and account data are now refused instead of being passed on to the player.
- **Docker**: the web container's access log no longer records the sign-in token included in playback, download and live update links.
- **Web interface**: a request the server does not answer now fails with an error after 15 seconds, or later for slow actions such as platform checks, connection tests and backups, instead of leaving the page waiting. Closing or reloading the tab also stops the requests the server was still working on for it.
- **Sign-in**: a failed sign-in now shows the server's reason instead of an internal server address.
- **Sessions page**: every session can now be reached through the page numbers. Before, the page count assumed 50 sessions per page while each page showed 20, so the sessions beyond the last page number could not be reached from the list.
- **Sessions page**: when the list fails to load, the page now says so and offers **Retry**, instead of reporting an empty library. A search or filter that matches nothing now says no sessions match and offers **Clear filters**.
- **Dashboard** and **API Keys** settings: a section that fails to load now shows the error with a **Retry** button, instead of loading forever or looking empty.
- **Lists**: when the streamers, media outputs, pipeline jobs, presets, workflows, templates, platforms or notification events list fails to load, the page keeps its header and search and shows the error with a **Retry** button. A pipeline, template, platform, engine, preset or workflow that cannot be opened now offers a link back to its list.
- **Lists**: the sessions list now turns on selection with a **Select** button in the page header and shows the same selection bar as the other lists. Empty lists look the same on every page, streamer cards show each platform's own icon and colour, and the global and theme settings place sections side by side only when the page is wide enough for them.
- **Lists**: deleting the last items on the last page of the sessions, media outputs, pipeline jobs, presets or workflows list now goes back to the previous page, instead of showing an empty page that says nothing was found.
- **Confirmations**: deleting a streamer or sessions now asks in an in-app dialog instead of a browser prompt, and deleting a streamer filter now asks first instead of deleting it at once.
- **Unsaved changes**: leaving the template, platform, engine, preset or workflow editor with unsaved edits now asks before discarding them. Global settings and the streamer editor, which already asked, now ask in an in-app dialog.
- **Live updates**: download, upload and check progress no longer stops for a while when your sign-in renews, including in a tab left in the background.
- **Browser notifications**: critical-event notifications now appear while the app's tab is in the background, instead of only once you return to it.
- **Streamer cards**: a recording that ended while the app's live connection had fallen behind no longer stays shown as recording, and check history and streamer status catch up as soon as the connection to the server comes back instead of staying out of date for several minutes.
- **Session page**: a session that is still recording now shows each new segment when it finishes, keeps its duration and size up to date, and shows when it ends, without reloading the page.
- **Job page**: a running job's page shows progress as it is reported and asks the server for updates far less often.
- **Job page**: a job with a long log no longer makes its page sluggish while it runs or while you scroll; only the log lines near the screen are drawn. Because of that, the browser's find only searches those lines, so the log now has a **Copy log** button that copies every loaded line, or downloads them as a file where the browser does not allow copying.
- **Job page**: deleting a job now asks in an in-app dialog and then opens the jobs list. Before, it went back to whatever page you came from, which left the app when the job was opened from a link.
- **Job page**: input and output sizes are shown in a fitting unit (KB, MB, GB) instead of always in MB, and their labels are translated.
- **FLV recordings**: files recorded with the Mesio engine now list Mesio as their creator instead of an outdated version number, and their real data size instead of 0, so media tools show correct file details.
- **FLV recordings**: with the Mesio engine and **Fix FLV Streams** on, when a stream restarted mid-broadcast, for example after the streamer turned on stream delay, the recording could become one very long file that players showed as 0 seconds long and that was never split by the duration limit. Recordings now keep counting time across such restarts and split as configured.
- **FLV recordings**: with the Mesio engine and **Fix FLV Streams** on, browser players can now show the length of a recording and seek in it when the stream sent no file information.
- **FLV recordings**: with the Mesio engine and **Fix FLV Streams** on, recordings of streams that send several conflicting setups before the picture starts now copy and convert correctly. Before, copying or converting such a file could keep the earlier setup instead of the one the stream settled on.
- **FLV recordings**: with the Mesio engine and **Fix FLV Streams** on, recordings of streams whose timing starts slightly before zero could shrink to a few seconds or have audio and video out of sync by seconds. Such recordings now play from the start with audio and video in sync.
- **FLV recordings**: with the Mesio engine, recordings now store their exact length instead of rounding it down to whole seconds, so players show the right length and the end of the seek bar matches the end of the recording. The session page's **Recordings** tab shows the exact length too.
- **Huya**: ordinary chat messages are now recorded without a colour, so they appear white in converted subtitles and burned-in videos instead of blue. Messages Huya colours still keep their colour. Chat files recorded before this update keep the blue.
- **Twitch**: a channel that has just gone live or just ended is now reported as offline until its stream can be played, instead of failing the live check with an error. When Twitch refuses playback, its own error message is shown.
- **Twitch**: a channel that does not exist is now shown as not found, and a suspended channel as banned, instead of failing every live check with a data error.

- **Twitcasting**: the **Stream Password** platform setting now unlocks password-protected broadcasts. Before, only a password added to the streamer URL (`?password=...`) worked; a password in the URL still takes priority.
- **YouTube**: a link to an uploaded or finished video is now reported as offline instead of live, so it is no longer recorded again on every live check. Live broadcasts are unaffected.
- **Screen readers**: search boxes, filter menus, switches, sliders and buttons that show only an icon, such as the round add buttons and **Clear filters**, now have names that screen readers announce. Filter buttons on the sessions, pipeline jobs and notification events pages now say whether they are on, and settings that were announced without their label, such as the Huya and TikTok API mode, now read their label.
- **Keyboard and touch**: buttons that only appeared under the mouse pointer, such as **Interact** on notification events, the step buttons in workflows and the remove button on **Logging** settings, now show on touch screens and when reached with the keyboard. The **Browser Notifications** or **Desktop Notifications** card, the platform sections of a template, the play button on a session's preview and selecting sessions can now be used from the keyboard.
- **Chinese interface**: form errors, such as on sign-in, password change, streamer, workflow, notification channel, template and preset forms, now appear in Chinese instead of English. The date picker shows Chinese month and day names, numbers on the session page and API keys dates follow the app language instead of the browser's, and the startup screen, several card labels, encoder preset descriptions and screen reader labels are translated.
- **Session page**: when the page is narrowed, such as with the sidebar open, the **Danmu Statistics** tiles now wrap onto more rows instead of squeezing four into one row.
- **Backup & Restore**: after importing a configuration, notification channels and their subscriptions, presets, workflows, proxies and any open streamer, template or engine page now show the imported settings without reloading the page.
- **Copy buttons**: when the browser refuses to copy, for example when the app is opened over plain HTTP on a local network, copying a file path, API key, MCP configuration or notification event now says it failed instead of reporting success or showing nothing.
- **Health**: a component that has not been checked yet is now shown in grey on the dashboard, the health page and the storage bars, instead of red on the dashboard and green on the storage bars.
- **Session page**: a session that has ended no longer shows a green live dot on the streamer's picture, and a session that is still recording counts its duration up instead of showing the length it had when the page was opened.
- **Workflows**: searching the step library while typing with an input method, such as pinyin, no longer searches with the unfinished text.
- **Logging and streamer pages**: when the log file list or a streamer's status check history fails to load, the page now shows the error with a **Retry** button instead of an empty area.
- **Streamer page**: opening a streamer's page shortly after enabling, disabling or batch-editing it from the streamers list now shows the change, and an open streamer page catches up when the connection to the server comes back.
- **Workflows**: the step library now lists workflows created or changed moments before, instead of the list it showed earlier.
- **Session page**: chat message times in the danmu list now follow the app language instead of the browser's.
- **Backup & Restore**: the size of the file chosen for import is shown in a fitting unit (KB, MB) instead of always in KB.
