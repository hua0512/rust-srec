# Release Notes

## `unreleased`

## New features

- **Batch detection for Bilibili and Twitch:** A new **Batch Detection** platform setting asks Bilibili or Twitch whether up to 100 streamers are live in one request, so streamers that are still offline are not checked one by one and monitoring many streamers is less likely to be rate limited. It is off by default and can be set differently for a template or streamer. In exchange, a stream start can be noticed up to a quarter of the check interval later, and because that request does not use an account, an expired login may only be noticed once the streamer goes live. Checks answered this way are drawn differently in the streamer's check history. See [Batch detection](https://docs.srec.rs/en/platforms/#batch-detection).

## Workflows and file processing

- Fixed the **Max Uploads** setting having no effect. rclone uploads were limited only by **Max IO Jobs** and took slots from moves and copies, and Baidu Netdisk uploads were not limited by either, so setting Max Uploads to 1 could still run several uploads at once. Now Max Uploads limits rclone and Baidu Netdisk uploads together, and uploads no longer count against Max IO Jobs. Baidu Netdisk uploads still run one at a time. Max Uploads defaults to 3, so if more uploads than that used to run at once, raise it. Lowering either limit applies right away; raising it above the value rust-srec started with needs a restart.
- Fixed a workflow step's own timeout not applying to **execute** steps. The command was still stopped at the global **Execute** timeout (1 hour by default), so a step allowed to run for longer failed early. A step's timeout now replaces the Execute timeout for that step.
- Fixed a cancelled or timed-out Baidu Netdisk upload overlapping with the next one. The next upload could start while the stopped BaiduPCS-Go was still shutting down, and two BaiduPCS-Go processes writing its local state at once can damage it. Now the next upload waits until the stopped one has exited, saying so in its log, and signing in from the account card reports that BaiduPCS-Go is busy until then.
- Fixed rclone uploads trying more times than the preset's Max Retries allowed. rclone retried each failed upload up to 3 times on its own before the next retry started, so a failing upload could run up to three times as often as configured, with no sign of it in the job's progress. Now each try shown in the job's progress is a single upload, and Max Retries limits the total. Presets can still pass `--retries` in their extra arguments to restore rclone's own retries.
- Fixed deleting or renaming a job preset or workflow that a pipeline still uses. Pipelines in the global settings, platforms, templates, streamers and other workflows refer to presets and workflows by name, so deleting or renaming one left those pipelines failing when they ran. Now the change is refused and a dialog lists where it is still used, with a link to each. A replace-mode configuration import also keeps omitted presets and workflows that the imported pipelines still use, listing them as warnings.

## Web interface

- The global settings page now warns when **Max Uploads**, **Max CPU Jobs** or **Max IO Jobs** is raised. Lowering these limits applies right away, but raising one above the value rust-srec started with only takes effect after a restart, which was previously mentioned only in the server log.
- Template cards now show how many streamers use each template under **Used by**, with a link to those streamers. Deleting a template that streamers still use now explains why it can't be deleted and offers **Show streamers**, instead of showing a raw server error.
- Fixed the web interface not recognising several server responses and showing a generic error or the server's raw message instead. Sessions without danmu statistics showed a load error with **Retry** instead of saying the statistics are not available, and refreshing an expired stream in the player failed instead of fetching the stream again. A proxy name that is already taken, a proxy with the same address and username, a proxy changed elsewhere, and a site that already has an account profile showed the server's message instead of an explanation or the list of settings that still use them. Cancelling a pipeline that had just finished reported an error, a session whose password must be changed was only sent to the change-password page on the next page load, and the sign-in error shown when the server could not be reached was not translated. The desktop app was not affected.
- Fixed fields that take a list of entries, such as keyword filters, stream selection and email recipients, adding unfinished text when typing with a Chinese or Japanese input method. Pressing Enter to pick a candidate added what had been typed so far, such as the pinyin letters, as an entry. Enter now adds an entry only after the input method has finished.
- Fixed the streamer list returning to the first page after saving a streamer, using the back arrow on its edit page, or cancelling **Add a streamer**. The list now reopens on the page you left, with the same search, filters and sorting.
- Fixed the **Per page** picker disappearing from lists such as streamers, pipeline jobs and job presets once everything fit on one page. Choosing a larger page size left no way to switch back to a smaller one. The picker now stays visible while a smaller size would split the list into pages again.
- By default, the streamer list now orders streamers within each state by when they last went live, most recent first, instead of by priority. Live streamers still come first and streamers with errors next, followed by offline streamers, which now come before disabled ones. A streamer that just finished streaming is no longer buried below disabled streamers or ones that have not streamed in months. Live streamers on the dashboard are now listed by when they went live too. Sorting by **State** now uses the same order instead of an alphabetical one that put live streamers in the middle of the list. Sorting by name now ignores upper and lower case.
- Fixed the **Custom** date range on the sessions page leaving out its last day. Sessions that started on the end day were not listed, so picking a single day showed almost nothing. The range now includes the whole end day, and picking only a start day shows that day's sessions.
- Fixed some fields not being connected to their labels, including the password on the sign-in and change-password pages, a job preset's ID and description, and a streamer's name. Clicking the label did not move to the field, screen readers did not announce the field's name or its error, and an invalid entry was not outlined in red.
- Fixed password managers handling rust-srec's password fields poorly. Changing your password gave them no sign of which saved login it belonged to or which fields held the new password, so the new password could fail to be saved. The password and token fields for other services, such as email, webhook, Telegram and Gotify notifications, stream passwords and Baidu Netdisk sign-in, could be filled in with your rust-srec login; browsers no longer offer it there.
- Fixed phones and tablets capitalising or autocorrecting the username on the sign-in page. Usernames are case-sensitive, so an automatically capitalised first letter made signing in fail.
- Fixed the theme mode and sidebar options on the **Theme** settings page not working from the keyboard. They could not be reached with Tab or chosen with Enter or Space, and screen readers did not say which option was selected.
- Fixed tall dialogs running past the bottom of a small window or phone screen, leaving their buttons out of reach because the page behind cannot scroll. Dialogs now fit the window and scroll inside.
- Fixed durations showing English units such as "2h 5m" in the Chinese interface, including session and recording lengths, the duration of an active download, server uptime on the **System Health** page, the average job duration, and how long a file operation has not been responding.
- The web interface now uses less CPU while its browser tab is in the background during recordings and uploads. Download, upload and job progress is no longer redrawn twice a second in a background tab, and catches up as soon as the tab is shown again.
