# 配置解析

`MergedConfigBuilder` 逐层应用配置，`ConfigResolver` 读取数据库记录并构建有效配置，`ConfigService` 缓存结果并向运行时服务广播更新。

用户配置的继承规则见[配置层级](../concepts/configuration.md)，JSON 字段见[覆盖配置参考](../reference/configuration-overrides.md)。

## 合并结果：`MergedConfig` {#合并结果-mergedconfig}

`MergedConfig` 是运行时用于监控、下载、弹幕和管道的最终配置。

主要字段（按用途分组）：

- 输出：`output_folder`、`output_filename_template`、`output_file_format`
- 限制：`min_segment_size_bytes`、`max_download_duration_secs`、`max_part_size_bytes`
- 弹幕：`record_danmu`、`danmu_statistics`
- 网络：`proxy_route`（解析后的连接方式，见[代理连接](#proxy-routes)）、`credential_policy`
- 引擎：`download_engine`、`extractor`、`download_retry_policy`、`engines_override`
- 流选择：`stream_selection`
- 管道：`pipeline`、`session_complete_pipeline`、`paired_segment_pipeline`
- 平台提取器选项：`platform_extras`
- 时序：`fetch_delay_ms`、`download_delay_ms`、`offline_check_count`、
  `offline_check_delay_ms`
- 会话体验：`auto_thumbnail`

部分设置属于全局运行时参数，不在 `MergedConfig` 之内，例如并发上限和日志过滤指令。

## 热重载、缓存与更新事件 {#热重载、缓存与更新事件}

`ConfigService` 在内存中缓存解析出的主播配置：

- TTL：1 小时（默认）
- 并发请求去重：同一主播同时只有一次解析在进行
- 解析硬超时：30 秒（避免进行中的条目卡死）

通过 API/界面修改配置时，该服务会让相关缓存条目失效，并广播 `ConfigUpdateEvent`，
以便调度器和各管理器作出响应。

典型的失效范围：

- `GlobalUpdated`：所有主播失效
- `PlatformUpdated`：该平台下的主播失效
- `TemplateUpdated`：使用该模板的主播失效
- `StreamerMetadataUpdated`：该主播失效
- `EngineUpdated`：所有主播失效（引擎的使用情况未被追踪）
- 编辑或删除已保存的代理：所有主播失效，并发布 `GlobalUpdated`

::: tip 优先使用模板
把共用设置放进模板，而不是在每个主播上重复配置。之后修改一次模板即可让所有关联主播
重新解析配置，无需逐个主播修改。
:::

启动时，以及全局、平台或模板配置修改后，已解析的离线检查设置会同时为最多
十六个独立主播刷新。运行时事件处理器仍会等待当前批次完成，再处理下一个事件。
单个查询失败会保留该主播原有的元数据设置，不会阻止其他主播刷新；已标记为待
删除的主播仍不进入批量快照。这只改变刷新调度，不改变配置优先级或持久化恢复
的确认条件。

## 过滤器快照

监控检查共享不可变的过滤器快照，包括空结果。最多缓存 1,024 个主播，同时执行的仓库
加载最多为 16 个；同一主播的并发检查合并为一次加载，单次加载在 10 秒后超时。保持
过滤器顺序和跳过无效记录的行为；取消或失败会释放等待中的检查。

成功修改过滤器后，先使共享快照失效，再安排重新检查。导入、删除主播以及全局或广播
丢失后的协调，也会使相关快照失效。已持有快照的检查使用该版本完成；失效的旧加载不能
重新发布缓存。直接 SQL 或共享运行时之外的写入，最多会在 30 秒缓存 TTL 内保持不可见；
过期后的下一次检查会重新加载。

## 托管凭据的持久化与执行

策略只包含凭据 ID，不复制秘密。选择保存为 `credential_selections` 的行，每个平台、每个模板与平台的组合或每个主播各一行，有序的凭据位于 `credential_selection_members`；API 和备份把它们作为 `credential_selection` 放在平台、模板覆盖或主播配置中，仓储层在写入时拆出、读取时放回。没有对应行的作用域交由下一层决定（在平台层表示不使用账号），因此 `inherit` 从不存储；`none` 终止认证继承。凭据配置归属于平台，SQLite 保证每个成员都属于其选择所在的平台，并拒绝删除被选中的凭据。删除平台、模板或主播，主播被标记删除，或主播移到另一个平台时，SQLite 也会删除其选择。各模式的成员数量、正在清理的凭据以及所有者所在平台在写入选择时检查。选择不在配置行内，因此只修改选择的主播写入会显式使该主播的合并配置失效。配置本身从不保存账号材料：携带 Cookie、令牌或账号登录信息的写入会被拒绝。缓存解析后的策略，在执行时读取当前秘密材料。

凭据配置出现之前的数据库会在启动时转换一次：只要 `legacy_credential_upgrade_pending` 标记表存在，`run_migrations` 就会在 SQL 迁移之后执行转换，并在同一事务中删除该标记。删除旧 `cookies` 列的迁移会把其值保存在 `legacy_cookies` 中，由该转换读取后随标记一起删除。导入旧备份时，会在校验前对备份内容执行同样的转换。

材料修订号防止刷新、健康检查和登录的过时结果写回；标签编辑另有乐观锁版本。策略、凭据和导入操作通过拥有独立生命周期的提交后工作发布，HTTP 请求取消不能撤销已提交配置的发布。导入按平台名对应凭据配置，保留空闲 UUID，拒绝被其他平台凭据占用的 UUID，不按名称/秘密猜测。导入的凭据先于选择它们的配置写入，二者位于同一 SQLite 事务。

录制绑定持久化身份、材料修订号、策略代次及 epoch，不保存秘密。账号或修订号变化时必须重新提取完整媒体包，不能把当前 Cookie 附加到旧 URL。活动会话引用阻止物理删除。替换导入持久化清理意图，在事务外结束相关工作，引用消失后才清理凭据。配置备份排除运行时绑定、托管凭据健康状态、轮询游标、二维码会话及播放上下文。

平台共享准入覆盖匿名、原始和托管提取、刷新及二维码操作；平台要求的重试间隔最长为 15 分钟。逻辑时限包括准入、锁和修复等待，嵌套调用不会重复收费。准入退避按平台和 `RouteKey` 区分：直连、系统代理或某个已保存的代理，与由哪个作用域或账号选择无关；未检测到环境变量代理时，系统代理的键等同于直连。账号认证失败，或限流且另一个候选账号使用不同连接时，才会故障切换；令牌桶速率仍按平台计算。协调仅限进程内；多个后端共享 SQLite 不保证公平轮询或唯一平台刷新。SQLite 修订号校验防止过时写入，不提供分布式执行协调。

## 代理连接 {#proxy-routes}

已保存的代理是 `proxies` 表中的行：名称不区分大小写且唯一，URL 为规范化的
`scheme://host[:port]`，用户名和密码可选且成对保存。URL 加用户名上的唯一索引保证一行对应一个出口。
全局、平台、模板、主播和账号的行保存 `proxy_route`（`inherit`、`direct`、`system` 或 `proxy`）以及
引用 `proxies` 的 `proxy_id`（`ON DELETE RESTRICT`）；全局连接方式不能为继承。主播被标记删除时，
触发器会重置其连接方式，使其不再占用代理。API 把主播的连接方式放在 `streamer_specific_config` 中，
仓储层在写入时把它拆出、读取时再放回，与凭据选择相同。配置写入只有在请求给出连接方式时才会修改它，
因此内部写入不会覆盖它。

解析取第一个非继承的层（主播、模板、平台、全局），得到 `ResolvedRoute`：包含所有 HTTP 客户端和引擎
使用的 `ProxyTarget`（直连、系统代理或显式端点）、用于准入的 `RouteKey`，以及供界面显示的决定来源。账号自己的连接方式会在其
凭据快照中替换操作的连接方式，提取、下载、弹幕和托管播放随后共用该快照；账号自身的管理调用依次解析
账号、平台、全局的连接方式。引用不存在的代理会报错，绝不会改为直连。系统代理读取启动时的环境变量快照，
弹幕和准入键使用该快照；进程内的客户端则由其自身按环境变量和操作系统设置查找代理。

引擎接收 `ProxyTarget`。为 `Direct` 时，FFmpeg 和 Streamlink 命令会从环境中移除 `HTTP_PROXY`、
`HTTPS_PROXY`、`ALL_PROXY` 和 `NO_PROXY`（大小写两种形式），Streamlink 提取器也一样。FFmpeg 在启动前
拒绝 `http` 以外的显式代理。

代理的写入由 `ProxyService` 负责。修改代理的 URL 或用户名时，固定使用它的每个账号都会进入新修订号，
其健康状态被丢弃，该代理的准入退避也会清除；重命名或只修改密码则不会。已解析的快照保留解析时的连接方式。

迁移安装的 `legacy_proxy_upgrade_pending` 标记表会让 `run_migrations` 在凭据转换之后，把旧的
代理设置和主播键转换一次，并在同一事务中删除标记。之后的一个迁移会删除旧的 `proxy_config` 列，
并把其值保存在 `legacy_proxy_settings` 中，由该转换读取后删除。备份按名称引用代理，
不携带 ID；导入旧备份时会对备份执行同样的转换，但不使用环境变量规则。
