# 持久化约定

面向修改数据库事务和导入行为的贡献者。运维操作见[备份与恢复](../operations/backup-restore.md)及[删除语义](../operations/data-governance.md)。

## 导入持久化所有权 {#导入持久化所有权}

导入与普通仓库写入共享同一套类型化字段绑定。导入仍在一个 SQLite 写事务中处理
全部十类配置，以及订阅/过滤器替换、邮箱交换和认证失效操作。现有 ID 与创建时间
保持稳定，保留调用方选定的更新时间和原始 JSON。备份格式未包含的提取器设置保留
现有值，新记录也保留相同的省略列默认值。

只有提交成功后才会使缓存失效并发布运行时通知。后续校验或数据库失败会回滚导入，
不发布变更；提交后的重载失败仍作为已提交状态的警告返回。

## 并发数据库更新 {#并发数据库更新}

并发删除同一媒体产物记录时，只会从会话总大小中扣减一次。总大小更新失败时，
记录删除也会回滚。这一数据库保证并不使可选的磁盘文件删除具备事务性。

模板凭据刷新在同一个预留写事务中读取和更新模板，保留在其之前提交的其他配置
编辑。并发增加主播错误计数时，每次调用返回各自更新产生的计数值。

## 批量查询

管道任务列表通过去重后的主播 ID 批量查询显示名称，每次查询最多 500 个 ID。
任务顺序和响应字段保持不变；主播不存在时仍不提供显示名称。批量查询失败时
会逐个重试，保留能够读取的名称，而不会让整个任务列表失败。
