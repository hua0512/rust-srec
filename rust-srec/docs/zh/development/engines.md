# 录制引擎内部实现

面向修改子进程管理和录制事件的贡献者。引擎选择和配置见[录制引擎](../concepts/engines.md)。

## 停止 Streamlink 录制 {#停止-streamlink-录制}

在 Unix 上，停止录制会向 Streamlink 进程发送 SIGTERM。隐藏的 Windows 子进程没有
控制台信号约定，因此不会收到停止请求。随后后端最多等待三秒让 Streamlink 退出，
超时则强制终止其受控进程树。标准输出转发及标准错误处理会持续到管道读到 EOF，
之后关闭 FFmpeg 的标准输入，让其完成输出收尾。

强制结束 Streamlink 属于正常停止，不视为失败：FFmpeg 会为管道关闭前转发的全部字节
完成收尾，仍缓存在 Streamlink 内部的数据会丢失。清理错误、FFmpeg 失败和标准输出
管道失败仍会使本次录制失败。

这些进程、转发和重封装阶段使用本次录制剩余的停止期限，并为 FFmpeg 收尾预留时间。
后续应用关闭请求可缩短已经在停止的录制期限。必要的最终事件交付仍由原任务持有，
直到消费者接收：直接集成引擎的调用方必须持续读取事件通道；停滞消费者由工作进程
整体强制退出上限约束。超过期限仍会强制终止受控进程树，并可能截断尾部。

两个子进程树继续受到约束，包括直接父进程退出后留下的后代。在 macOS 上，主进程
退出竞争仅使用剩余的进程树清理预算，不增加新的宽限期。该约束假定后代不会主动
逃离进程组或 Windows Job Object。

## 录制文件名与状态跟踪 {#录制文件名与状态跟踪}

录制模板会展开配置中的日期标记，而主播名称和标题中的百分号保持字面含义。
例如，标题 `Top 5%d` 仍为 `Top 5%d`，不会替换成当月日期。启动时的输出根探测
使用相同的元数据字面值规则。

FFmpeg 录制与 Streamlink 重封装需要 info 级别日志和统计信息来跟踪分片及进度。
后端在最后提供 `-loglevel info -stats` 参数，因此自定义静默日志参数和 `-nostats`
不会关闭这些必要信息。
