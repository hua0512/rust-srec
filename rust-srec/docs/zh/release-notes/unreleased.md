# 更新日志

## `unreleased`

## 升级前须知

- **移除的设置：** Bigo 的 **签发完整性 token** 设置已移除，因为 Bigo 检测已不再需要该项。更新时会自动从已保存的平台、模板和主播设置中清理该设置。详见[录制与恢复](#录制与恢复)。
- **Bigo 录制：** Bigo 直播间现在默认录制 App 端的原始高清流，新录制的文件将变为 FLV 格式（多为 HEVC 编码，不再是 H.264 的 TS 文件），且无论原本配置了什么引擎，都会由 Mesio 引擎录制。如果直播流中途切换画质，同一场录制可能会拆分成多个文件。对 HEVC 文件进行转封装、转码等后处理需要 FFmpeg 6.1 或更新版本，且并非所有浏览器都能直接在网页播放器中播放。如需保持原来的网页版录制方式，请在 Bigo 平台设置中关闭 **录制原始直播流**。参见[录制](https://docs.srec.rs/zh/platforms/bigo#recording)。
- **通知代理：** Webhook、Telegram、Gotify、Discord 通知以及浏览器推送现在改用应用内的 **默认代理**，不再自动读取服务器的代理环境变量。除非 **默认代理** 设为 **系统代理**，否则更新后它们的连接方式就会改变。若此前依赖 `HTTP_PROXY` 或 `HTTPS_PROXY` 发送通知，请在更新后把对应渠道的代理设为 **系统代理**（浏览器推送始终跟随 **默认代理**，邮件通知仍保持直连）。参见[通知代理](https://docs.srec.rs/zh/concepts/notifications#proxy)。
- **上传代理：** rclone 和百度网盘上传现在改用应用内的 **默认代理**，不再自动读取服务器的代理环境变量。若此前依赖 `HTTP_PROXY`、`HTTPS_PROXY`、`RCLONE_HTTP_PROXY`、rclone 的 `--http-proxy` 参数或 BaiduPCS-Go 自身的代理设置进行上传，请把对应步骤的代理设为 **系统代理**；否则 rclone 会忽略环境变量，仍带有 `--http-proxy` 参数或 BaiduPCS-Go 自身代理设置的上传会直接失败，直到移除这些旧配置。参见[上传代理](https://docs.srec.rs/zh/reference/processors#upload-proxy)。

## 新增功能

- **哔哩哔哩和 Twitch 批量检测：** 新增平台设置 **批量检测**，一次最多可同时查询 100 位哔哩哔哩或 Twitch 主播的开播状态，减少对未开播主播的逐个查询，监控大量主播时更不容易被限流。该设置默认关闭，支持按模板或主播单独开启。开启后，开播最多可能晚四分之一个检查间隔才被发现；由于批量查询不使用账号，登录过期也会等到主播开播时才会察觉。批量检测的结果会在主播的检查历史中以不同样式区分。参见[批量检测](https://docs.srec.rs/zh/platforms/#batch-detection)。
- **Bigo 开播通知：** 现在可以通过 BIGO 官方开播推送监控 Bigo 主播。在 Bigo 平台设置中开启 **批量检测** 并选择一个已登录的 BIGO 账号后，主播开播几秒内即可收到通知并开始检测，未开播的主播也无需频繁逐个查询（仅至少每 10 分钟完整复核一次）。注意：该账号会自动关注你监控的所有 Bigo 主播（对方可见），且不要同时在 BIGO App 中登录，否则会互相踢下线。未开启推送时仍使用轮询（可能会延迟发现开播或漏录短时直播），主播卡片和设置页会标明当前方式。如果收不到推送或断连超过 5 分钟，系统会自动回退到轮询并在主播列表和通知中提醒你，也可以在 Bigo 设置中点击 **立即重新连接**。参见[开播通知](https://docs.srec.rs/zh/platforms/bigo#live-notifications)。
- **Bigo 原画录制：** Bigo 直播间现在默认录制 App 端的原始高清流（通常为 720p 或 1080p 的 HEVC，画质高于网页版的 540p H.264），且无需登录账号。遇到多人连麦、密码房（平台默认密码对所有主播生效）或原始流无法录制时，会自动改录网页版直播流。如需默认录制网页版，请关闭 **录制原始直播流**；在 **首选格式** 中将 HLS 排在最前也会优先尝试网页版，失败后再回退到原始流。详见[升级前须知](#升级前须知)，另参见[录制](https://docs.srec.rs/zh/platforms/bigo#recording)。
- **微博扫码登录：** 现在可以直接用微博 App 扫码添加微博账号，不再需要从浏览器复制 Cookie。账号仍为可选项，即使不登录或账号过期也不会中断微博主播的监控和录制。账号会在每天首次使用或点击 **校验** 时验证登录状态：扫码登录的账号被登出后会自动续期，无需重新扫码（仅在自动续期失败或需要重新登录时通知你）；手动粘贴的 Cookie 不会自动续期，失效后会发送 **凭据无效** 通知。参见[微博](https://docs.srec.rs/zh/platforms/others#二维码登录)。
- **主播检测持续失败提醒：** 通知渠道现在可以订阅 **主播检测持续失败** 和 **主播检测已恢复**。当某位主播的检测或录制连续多次失败、开始延长重试间隔时，会发送一次提醒并注明平台和最近的错误；待检测重新成功或录制恢复正常后再发送恢复通知。该功能适用于所有平台，不用一直盯着主播页面也能及时发现平台故障或改版。参见[通知系统](https://docs.srec.rs/zh/concepts/notifications#优先级)。
- **通知渠道代理：** Webhook、Telegram、Gotify 和 Discord 渠道新增 **代理** 设置，方便将通知送达服务器所在地无法直接访问的服务（例如在中国大陆使用 Telegram）。渠道默认跟随 **默认代理**，也可单独选择 **直连**、**系统代理** 或已保存的代理；修改后无需重启，对后续通知和测试通知立即生效。**代理** 页面会列出各代理正在被哪些渠道使用，仍在使用中的代理无法删除。邮件渠道始终保持直连。参见[通知代理](https://docs.srec.rs/zh/concepts/notifications#proxy)。
- **上传代理：** rclone 和百度网盘上传步骤新增 **代理** 设置，方便上传至服务器所在地无法直连或速度较慢的云存储。步骤默认跟随 **默认代理**，也可以在任务预设或工作流步骤中单独选择 **直连**、**系统代理** 或已保存的代理。**代理** 页面会列出各代理正在被哪些任务预设和流水线使用，仍在使用中的代理无法删除。配置备份也会保留每个步骤的代理设置。参见[上传代理](https://docs.srec.rs/zh/reference/processors#upload-proxy)。

## 录制与恢复

- 哔哩哔哩和 Twitch 开启 **批量检测** 后，一旦批量查询发现多位主播开播，符合条件的主播会立即进行单独检测并尽快开录，不必等到各自的下一次定时检查；如果首次检测还没拿到开播状态，后续每次批量查询只要仍显示在直播，都会继续立即重试。
- 修复了 Bigo 尚未判断直播间是否开播就因要求登录而检测失败，以及受限账号把开播直播间误判为未开播、导致漏录的问题。现在开播状态直接通过公开信息查询，未开播的直播间无需账号也能正常检测；账号仅在需要获取网页版直播流时使用。如果 Bigo 静默限制了某个账号（不登出，但让它看到的直播间都显示未开播），系统现在会在核实直播确实在进行后，将该账号暂停使用 30 分钟；开启故障切换的账号池会自动切换至下一个账号。参见 [Bigo](https://docs.srec.rs/zh/platforms/bigo)。
- 修复了微博账号失效后，微博用户主页链接（如 `https://weibo.com/u/{uid}`）每次检测都报“Extraction failed”且无任何通知的问题。现在默认以游客身份查询，不再依赖账号登录；仅在微博拒绝游客访问时才使用账号，若账号已登出，扫码账号会自动重新登录，其他账号则会标记为需重新登录并发送 **凭据无效** 通知。参见[微博](https://docs.srec.rs/zh/platforms/others#微博)。
- 微博现在还支持 `m.weibo.cn/u/{uid}`、`m.weibo.cn/profile/{uid}` 和 `weibo.com/{uid}` 链接，并会在主播未开播时显示其名称和头像。
- 修复了录制一直显示进行中却什么也没录到（空文件或无文件）的问题。此前在 HLS 直播持续刷新但拿不到视频分段，或 FLV 连接不断开却不发音视频数据时，录制不会被判定为失败。现在连续一段时间无音视频数据（HLS 为 60 秒，FLV 为 90 秒）会自动结束并报网络错误。FLV 的等待时长可在 Mesio 引擎 FLV 标签页的 **高级 → 下载** 中通过 **最大停顿时间** 调整。参见[停滞的流](https://docs.srec.rs/zh/concepts/mesio#stalled-streams)。
- HLS 中持续失败的分段现在重试 45 秒后即被跳过，不再导致录制卡住约两分钟（进行中的重试会先完成，等待限流的时间不计入）。该时长可在 Mesio 引擎 HLS 标签页的 **高级 → 分段下载** 中通过 **分段重试时限** 调整；DASH 录制同样适用 45 秒。
- 修复了在模板或主播中设置的 **弹幕关闭时结束录制** 不生效的问题。此前只读取平台设置，因此即使为某位主播关闭了该选项，弹幕提示下播时仍会停止录制。
- 修复了 **最小分段大小** 会在录制中途删掉正常片段、留下空缺的问题。直播中途切换分辨率或编码时会拆出新文件，低码率直播在两次切换之间录下的片段可能小于该阈值（默认 1 MiB），此前会连同弹幕一起被删除。现在因画质或编码切换产生的小文件会保留，而因停止录制、断流重连或插播广告产生的过短文件仍会被清理。参见[资源限制](https://docs.srec.rs/zh/reference/settings#资源限制-resource-limits)。
- 降低了开启 **循环保护** 进行 FLV 录制时以及累积大量历史 **弹幕统计** 后的服务器内存占用。
- 将 **弹幕统计** 中的 **保留高频词数量** 设为 `0` 后，可在保留会话的弹幕总数、活跃度时间线、发言人和礼物排行等统计的同时，单独关闭词频统计与中文分词。

## 工作流与文件处理

- 修复了待处理任务超过 10,000 个时，重启后所选处理器已不可用的任务仍卡在队列中等待的问题。现在无论积压多少任务，这类任务都会在启动时自动标记为失败。
- 修复了 **最大上传数** 设置不生效的问题。此前 rclone 上传实际上受 **最大 IO 任务数** 限制（还会占用移动、复制等任务的名额），而百度网盘上传不受任何限制，导致设为 1 仍会并发上传。现在 **最大上传数**（默认为 3）统一限制 rclone 和百度网盘上传，不再占用 **最大 IO 任务数**；百度网盘上传仍按顺序逐个执行。如果之前同时上传的任务超过 3 个，请调高该设置（调低立即生效，调高到超过启动时的值需重启生效）。
- 修复了工作流步骤自身的超时设置对 **执行** 步骤不生效的问题。此前命令仍会在达到全局 **执行超时**（默认 1 小时）时被强行终止，导致允许运行更久的步骤提前失败。现在步骤自身的超时设置会覆盖该步骤的全局 **执行超时**。
- 修复了已取消或超时的百度网盘上传尚未完全退出时，下一次上传就提前开始、可能损坏 BaiduPCS-Go 本地数据的问题。现在下一次上传会等待上一个进程完全退出并在日志中提示；等待期间若从账号卡片登录，会提示 BaiduPCS-Go 正忙。
- 修复了 rclone 上传实际重试次数超出预设 **最大重试次数** 的问题。此前 rclone 会在每次失败后自行重试最多 3 次，导致总执行次数最高可达配置上限的三倍，且任务进度中看不到这些隐藏重试。现在进度中显示的每次尝试都只执行一次上传，总次数严格按 **最大重试次数** 计算。如需恢复 rclone 自身重试，可在预设的额外参数中传入 `--retries`。
- 修复了仍被流水线使用的任务预设或工作流可以被误删或重命名、导致后续运行失败的问题。现在这类操作会被拦截，并弹窗列出所有仍在使用的位置（支持点击跳转）；以 **替换** 模式导入配置时，导入后流水线仍需用到的预设和工作流也会被自动保留并在警告中提示。

## 配置

- 修复了模板的平台覆盖或主播 **平台选项** 标签页中，开关类选项（如 **批量检测**、**强制原画质量**、**弹幕关闭时结束录制**）未单独设置时也只显示“开”或“关”、无法看出是否跟随平台设置的问题。此前一旦误点切换，只能通过编辑 JSON 恢复跟随。现在这类选项统一提供 **继承**、**开** 和 **关** 三态，选择 **继承** 即可沿用模板或平台设置。参见[配置层级](https://docs.srec.rs/zh/concepts/configuration#需要注意的合并规则)。

## Web 界面

- 修复了桌面应用中点击主播头像上的频道链接会进入恢复模式，而不是在浏览器中打开该频道的问题。
- 全局设置页现在会在调高 **最大上传数**、**最大 CPU 任务数** 或 **最大 IO 任务数** 时给出提示：调低这些限制会立即生效，但调高到超过启动时的值需要重启后才生效（此前只在服务器日志中提及）。
- 模板卡片现在会在 **使用情况** 中显示使用该模板的主播数量，并支持直接跳转查看。删除仍被主播使用的模板时，现在会说明原因并提供 **查看主播** 按钮，不再直接抛出原始服务器错误。
- 修复了网页界面无法正确识别部分服务器返回状态、转而显示笼统报错或原始英文提示的问题（桌面应用不受影响）。具体包括：无弹幕统计的会话现在会提示暂不可用而非加载失败；播放器中的过期直播流可正常自动刷新；代理冲突或账号配置重复时会显示中文说明及占用列表；取消刚结束的流水线不再报错；需要改密时会立即跳转改密页；服务器无法连接时的登录错误也已正常翻译。
- 修复了多项输入框（如关键词过滤、直播流选择、邮件收件人等）在使用中文或日文输入法时会误添未完成文字的问题。此前按回车选词时，拼音等未确认内容会被直接添加为条目，现在只有在输入法确认上屏后按回车才会添加。
- 修复了在主播编辑页保存、点击返回箭头或取消 **添加主播** 后，主播列表总是跳回第一页的问题。现在会回到离开时的页码，并保留原来的搜索、筛选和排序。
- 修复了主播、流水线任务、任务预设等列表在所有内容都能一页显示时，**每页** 选择器随之消失、导致选大之后无法调回较小每页数量的问题。现在只要较小的每页数量会重新分页，选择器就会保持显示。
- 优化了主播列表与仪表盘的排序方式：默认不再按优先级排列，改为在各状态内按最近开播时间倒序排列，整体状态顺序为“直播中 → 出错 → 未开播 → 已禁用”，刚下播的主播不再被压到已禁用或长期未播的主播后面。仪表盘上的直播中主播也按开播时间排列；按 **状态** 排序时沿用同一顺序（不再按字母顺序把直播中主播排到中间）；按名称排序现在不再区分大小写。
- 修复了录制会话页面的 **自定义** 日期范围漏掉最后一天的问题。此前结束日当天开始的会话不会显示，只选一天时几乎查不到结果。现在会包含结束日全天，只选开始日期时也会显示当天的会话。
- 录制会话等详情页顶部的导航路径现在显示简短 ID（如 `#6c333b6b`），鼠标悬停可查看完整 ID，不再直接显示一长串完整 ID，也不会把其中的部分字母错误转为大写。
- 修复了部分输入框未与标签关联的问题（包括登录和改密页的密码框、任务预设的 ID 和描述、主播名称）。此前点击标签无法聚焦输入框，屏幕阅读器也读不出字段名称和报错，输入有误时也不会标红框。
- 修复了浏览器和密码管理器无法正确识别密码框的问题：修改密码时现在能正常提示更新已保存的登录信息；同时，邮件、通知渠道、直播间密码和百度网盘登录等第三方服务的密码或令牌输入框，不再会被误填入 rust-srec 自身的登录密码。
- 修复了手机和平板在登录页会自动把用户名首字母大写或纠错的问题。由于用户名区分大小写，自动大写此前会导致登录失败。
- 修复了 **主题** 设置页中的主题模式和侧边栏选项无法用键盘操作的问题。现在可以通过 Tab 键切换焦点、用回车或空格选中，屏幕阅读器也能正常读出当前选项。
- 修复了在较小窗口或手机屏幕上，内容较多的对话框会超出屏幕底部、导致底部按钮点不到的问题。现在对话框会自动适应窗口高度并在内部滚动。
- 修复了中文界面中部分时长仍显示“2h 5m”等英文单位的问题，涵盖录制会话和片段时长、实时下载时长、**系统健康** 页面的服务器运行时间、任务平均时长，以及文件操作无响应时长。
- 录制或上传期间，网页界面切到浏览器后台标签页时会占用更少的 CPU：后台不再高频刷新下载、上传和任务进度，切回标签页时会立即更新到最新状态。
- 修复了主播页面中实时下载的速度、大小、分段和倍率数值一顿一跳的问题。现在这些数值会在两次更新之间平滑过渡，不再瞬间跳变后停住。
- 修复了会话 **弹幕统计** 中 **活跃发言用户**、**高频词**、**送礼排行** 和 **热门礼物** 四个图表的柱条全部显示为黑色、在深色模式下难以看清的问题，现在各图表已恢复原本配色。
- **引擎** 和 **代理** 设置页已改用与其他设置页一致的列表布局：每条引擎现在会显示配置摘要和快捷操作按钮，**系统代理** 拥有独立的状态卡片，每条代理也可以按需展开查看正在使用它的各项设置。
- 修复了扫码登录成功后二维码对话框不会自动关闭的问题。现在账号保存后，对话框会稍作提示并自动关闭。
- 在平台、模板或引擎设置页保存更改后，现在会留在当前页面，不再自动返回列表，方便继续调整其他标签页或设置，完成后再点击 **返回**。
