# 更新日志

## `unreleased`

## 新增功能

- **MPEG-DASH 录制：** Mesio 现在可以录制 MPEG-DASH（`.mpd`）流，包括直播和已结束的流。分开传输的视频和音频会合并为一个 MP4 文件。可在 Mesio 引擎新增的 **DASH** 选项卡中选择视频和音频质量、音频语言、直播录制起点以及下载限制；在**首选格式**中添加 `dash`，即可在平台提供 DASH 时优先使用。不支持 DRM 加密的流，网页播放器也无法播放 DASH 流。详见 [MPEG-DASH 录制](../concepts/engines.md#mpeg-dash)。
- **TikTok DASH 流：** TikTok 直播间现在会列出 MPEG-DASH 流，大多数画质（包括纯音频）均提供。FLV 仍然优先，默认录制 FLV，即使偏好的画质只以 DASH 提供；如需使用 Mesio 引擎录制 DASH，请在 TikTok 平台、模板或主播的**首选格式**中将 `dash` 放在第一位。详见 [TikTok](../platforms/tiktok.md)。

## 录制与恢复

- 修复 Mesio 在直播地址无法看出是 HLS 还是 FLV 时拒绝录制的问题，现在会使用平台报告的格式。
- 修复 Mesio 录制已结束的 HLS 流（回放或点播）时偶尔漏掉分片的问题：某个分片下载缓慢或需要重试、而其后的许多分片已下载完成时，该分片会被丢弃，录制仍正常结束却缺少这部分内容。高码率、分片较大的流同样受影响。
- 修复 Mesio 录制已结束的 HLS 流（回放或点播）时漏掉重复分片的问题：播放列表多次列出同一个分片时，只会录制最后一次出现的那个。
- 修复 Mesio 录制已结束的 fMP4 格式 HLS 流（回放或点播）时的卡死问题：当流在超过八个不同的初始化分片之间切换时，录制会在第一次切换处停住且永远无法结束。
- 修复开启 **强制使用移动端 API**，或因网页端数据不可用而改用抖音移动端数据时，正在直播的抖音直播间被识别为未开播、因而没有录制的问题。此时此前为空的主播名称和头像现在也会正常显示。
- HLS 流的分片全部下载失败时，Mesio 现在会报告具体原因（例如 HTTP 状态码或网络错误），而不是“流为空”。fMP4 流的初始化分片无法下载时，Mesio 会停止下载依赖它、只会被丢弃的媒体，因此这类尝试会更快结束。
- 修复服务器要求放慢请求（HTTP 429 “Too Many Requests”）时，Mesio 在几秒内就结束 HLS 录制或漏掉分片的问题。Mesio 现在会按服务器要求的时长（最多一分钟）暂停发往该服务器的请求，然后逐步恢复，而不是在几次请求被拒后就放弃。详见[限流](../concepts/mesio.md#rate-limiting)。
- 当 **HTTP 版本** 为 **自动**（默认）时，在服务器支持且连接不经过代理的情况下，Mesio 现在通过 HTTP/2 下载 HLS 和 DASH，用一个连接更快地获取分片。经过代理时以及录制 FLV 时，**自动** 仍使用更稳定的 HTTP/1.1。**仅 HTTP/2** 现在会真正使用 HTTP/2（此前该选项不起作用），因此选择它后，从不支持 HTTP/2 的服务器录制会失败。
- Mesio 的缓冲区大小设置（现为 FLV 选项卡中的 **读取缓冲区大小**）现在会对 FLV 录制生效，此前该设置被忽略。默认值改为 64 KiB，即 FLV 录制一直实际使用的大小。仍保留旧默认值 8 MiB 的引擎会在升级时改用新默认值，因此其录制不会开始占用更多内存。

## 工作流与文件处理

- 修复 rust-srec 恰好在工作流步骤失败时停止，导致该步骤丢失已安排的自动重试、下次启动时工作流被标记为失败的问题。
- 修复取消工作流后的提示未计入正在等待自动重试的步骤的问题。
- 工作流的进度现在会在步骤运行期间随之推进（适用于转封装、复制、压缩和上传等会上报进度的步骤），而不是只在某个步骤完成时才变化。失败的步骤不再计入进度，因此失败或已取消的工作流会显示其已完成的部分。
- 处理任务的实时进度不再每秒多次写入数据库，从而减少任务运行时的磁盘写入，并在数据库繁忙时保持进度持续更新。
- 转封装为 MP4 时，为快速启动重写文件期间现在会显示“正在收尾…”，不再看起来卡在 99%。
- 任务进度、顶栏和工作流步骤现在会显示正在处理的文件。
- rclone 和百度网盘上传现在会在任务日志中记录每次重试，并在任务进度和顶栏中显示当前是第几次尝试。rclone 上传还会显示正在发送的文件。
- 百度网盘上传现在显示整个任务的进度（字节数、文件数和正在上传的文件），不再每个文件都从头开始，每秒更新一次，并会显示正在等待其他上传完成。
- 复制和移动任务现在显示整个任务的字节数和剩余时间，压缩任务显示速度和剩余时间，转换多个弹幕文件时会显示当前进行到第几个文件。

## Web 界面

- 修复在笔记本和桌面窗口尺寸下，侧边栏占去部分宽度后，卡片、编辑器和详情页内容溢出或被挤压的问题。卡片列表现在按页面实际可用宽度排列列数，页面标题栏中的按钮会自动换行，过长的名称、标题、URL 和配置项以“…”截断，悬停可查看完整内容。
- 修复模板中的 Mesio 引擎覆盖。所有 HLS 与 FLV 设置以及 **修复 FLV 流**、**修复 HLS 流**、**修复 DASH 流** 开关现在都会显示所继承的引擎设置，并可选择沿用引擎设置、使用默认值或自定义值；此前未设置的开关显示为关闭，HLS 设置需先开启 HLS 修复才能编辑，且包含重置设置的模板无法保存。模板中不再为 **最大停顿时间** 和 **点播分段超时** 提供 **已禁用** 选项，因为模板从来无法真正关闭它们，请在引擎中设置。
- 重新设计 Mesio 引擎设置。现在 FLV、HLS 和 DASH 各有一个选项卡，先显示该格式的修复开关和大多数录制需要的设置，例如 HLS 的码流版本、User Agent 和查询参数，或 DASH 的质量和轨道；其余设置按用途归入 **高级**，例如连接、分段下载、缺口与停顿或缓冲。每个选项卡和分组会显示有多少项设置与默认值不同（或模板覆盖了多少项），**恢复默认值**（模板中为 **使用引擎设置**）可清除单个分组。关闭 HLS 修复时 HLS 设置不再锁定，因为它们始终生效；FLV 循环保护的内存上限和 HLS 进度更新设置现在也可以在表单中设置。**修复 HLS 不连续性** 更名为 **修复 HLS 流**。
- FFmpeg 和 Streamlink 引擎设置现在与 Mesio 一致：设置按分组显示，并标出有多少项与默认值不同；较少用的设置归入 **高级**；在模板覆盖中，每项设置都可以使用引擎设置（选项中会显示其值）、默认值或自定义值。模板中的无损分段现在会考虑引擎自身的设置，因此自定义参数来自引擎时也会显示相应警告。
- 保存引擎时现在只保存你设置过的项，而不是每项默认值，因此引擎会跟随今后默认值的变化。
- 保存引擎或模板时不再删除表单未显示的设置（例如通过 API 设置的项）；缺口策略、码率变体或 DASH 质量选项中被清空的数字现在会提示错误，而不是保存为 0。
- 移除了 Mesio HLS 缓冲设置中的 **直播重排窗口（毫秒）** 和 **直播重排窗口（分段）**：这两项设置从未生效，已保存的值会被忽略。
- 引擎设置页改为与代理相同的列表形式，显示每个引擎的类型、已安装版本和状态，并在旁边提供 **配置** 按钮。
- 任务页现在会为转封装、转码、字幕烧录、音频提取等 FFmpeg 步骤显示进度条、速度和预计剩余时间，显示多文件任务（例如 rclone 上传）当前进行到第几个文件、运行中任务的已运行时长，并在步骤超过一分钟没有进度时给出提示。失败和已取消的任务现在也会显示运行时长和排队时长。
- 转封装、转码、复制、压缩等耗时较长的处理步骤运行超过 10 秒后，会显示在顶栏中并实时显示进度。点击可查看每个步骤的主播、进度和剩余时间，或跳转到对应任务。
- 修复工作流步骤自动重试期间的任务页。等待下一次尝试的步骤现在显示为等待重试，并给出倒计时和下一次是第几次尝试，而不是显示为失败；重试开始后页面会跟随任务更新并显示当前是第几次尝试；也不再提供必然失败的**重试工作流**按钮。重试或取消失败时，提示现在会说明原因。已取消或失败的工作流中的任务不再显示不会执行的自动重试。
- 工作流页面现在会显示每个步骤是在排队、运行中还是等待自动重试，而不是把所有进行中的步骤都显示为处理中。运行中的步骤在报告进度时会显示进度条，步骤列表中以及鼠标悬停在图中的步骤上时会显示速度、剩余时间和文件信息；等待重试的步骤会显示何时再次运行。录制会话的处理任务选项卡现在会自动更新，并显示新开始的工作流。
- 处理管道页面打开时占用的处理器时间更少：运行中任务和工作流的状态图标与标签不再旋转或闪烁。
- 工作流图现在会根据步骤调整高度，几个并行的步骤不再被挡在框外（更大的图仍可拖动查看）；每个步骤以其步骤 ID 作为标题，使用相同处理器的步骤也能区分开。
- 点击 **重试所有失败任务** 后显示的提示现在已翻译。
