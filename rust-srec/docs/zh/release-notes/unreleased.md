# 更新日志

## `unreleased`

## 升级前须知

- **无效的环境变量值：** `API_PORT`、`ACCESS_TOKEN_EXPIRATION_SECS`、`REFRESH_TOKEN_EXPIRATION_SECS`、`REFRESH_TOKEN_REUSE_GRACE_SECS` 或 `MIN_PASSWORD_LENGTH` 的值无效时，rust-srec 现在会在启动时停止，而不再悄悄改用默认值。最常见的情况是值后面同一行还写有注释，例如早先示例环境变量文件中的 `ACCESS_TOKEN_EXPIRATION_SECS=3600 # 1 hour`：通过 `docker run --env-file` 或 systemd 服务的 `EnvironmentFile=` 加载时，这类值现在会导致启动停止，而此前会被悄悄忽略。更新前请检查这些变量。详见[配置](#配置)。
- **反向代理：** 网页界面现在会拒绝来自同一地址下其他端口或子域名页面的操作请求。如果网页界面位于会改写浏览器访问地址的反向代理之后，并且更新后所有操作都提示 "Request refused"，请让代理转发原始地址，或将该地址加入 `CSRF_TRUSTED_ORIGINS`。详见[认证与 API](#认证与-api)。
- **API 错误响应：** 请求体、查询参数或 URL 路径格式有误的请求，现在会返回带有 `code` 的 JSON 错误响应，而不再是纯文本。状态码不变。详见[认证与 API](#认证与-api)。
- **Streamlink 分片大小：** Streamlink 录制现在会在达到 **最大分片大小** 时结束当前分片并在新文件中继续录制（同时设置了 **最大时长** 时除外）。此前该设置对 Streamlink 录制不起作用。详见[录制与恢复](#录制与恢复)。
- **录制使用 `FFMPEG_PATH`：** 设置了 `FFMPEG_PATH` 时，**可执行文件路径** 留空的 FFmpeg 引擎现在会使用该 FFmpeg 录制，而不再运行系统路径中的 `ffmpeg`。详见[录制与恢复](#录制与恢复)。
- **旧版备份：** 此版本之前创建的备份不包含 **地址获取方式** 选项，因此导入这类备份会把所有平台和模板的 **地址获取方式** 设为默认值。更新后请重新创建备份。详见[配置](#配置)。
- **列表页码链接：** 之前保存的媒体产物、处理任务、预设和工作流列表的 `?page=` 链接，现在打开的会是原来的前一页，因为这些列表的页码现在从 1 开始计数。详见[Web 界面](#web-界面)。

## 新增功能

- **会话页面的录制弹幕：** 观看录像时，录制的弹幕会按视频时间显示在画面上。播放器中的**弹幕设置**面板可以屏蔽弹幕类型，调整不透明度、字号、速度和显示区域，合并重复弹幕，悬停时暂停弹幕，在进度条上方显示弹幕热度，并屏蔽关键词或用户。设置会被记住，大型弹幕文件加载时页面不会卡顿。参见[弹幕录制](../guides/danmu.md#观看带弹幕的录像)。
- **播放器页面的直播弹幕：** 在**播放器**页面播放直播时，弹幕会实时显示在画面上，同样可以用弹幕按钮和**弹幕设置**控制。网格中的每个播放器显示各自直播的弹幕，隐藏弹幕时不会接收弹幕。参见[观看带弹幕的直播](../guides/danmu.md#观看带弹幕的直播)。
- **磁盘空间不足通知：** 存放录制文件或数据库的磁盘用量达到 95% 时，现在会发送通知，注明是哪个文件夹以及还剩多少空间；在用量降到 80% 以下之前，该磁盘上的每个录制或数据库文件夹只发送一次。此前该事件虽然可以订阅，但从未发送过。参见[通知](https://docs.srec.rs/zh/concepts/notifications#存储严重事件)。
- **Twitch H.265 与 AV1：** 新增 Twitch 平台设置 **允许 H.265 (HEVC)** 和 **允许 AV1**，可录制部分频道仅以这些编码提供的更高画质。两项默认关闭，未开启时录制仍为 H.264。详见 [Twitch](https://docs.srec.rs/zh/platforms/twitch)。

## 录制与恢复

- **最大分片大小** 设置现在对使用 Streamlink 引擎的录制生效（同时设置了 **最大时长** 时除外）。此前 Streamlink 录制会超过该限制继续写入同一个文件；现在达到限制时会结束当前分片并在新文件中继续录制，与 FFmpeg 引擎一致。使用 Streamlink 录制的 MP4 文件在浏览器和播放器中也能更快开始播放，与 FFmpeg 引擎录制的文件相同。
- FFmpeg 引擎的 **可执行文件路径** 留空时，录制直播现在也使用 `FFMPEG_PATH` 环境变量指定的 FFmpeg。此前即使处理任务使用了 `FFMPEG_PATH`，这类引擎仍会运行系统路径中的 `ffmpeg`。参见[环境变量](https://docs.srec.rs/zh/reference/environment)。
- 修复中文、日文等多字节文字的较长直播标题使文件名超出磁盘限制、导致录制无法保存的问题。现在文件名和文件夹名中的标题会被缩短，名称的其余部分（例如日期和时间）保持不变。
- 使用 Mesio 引擎录制的 FLV 文件现在会将创建者记录为 Mesio（此前为过时的版本号），并记录实际的数据大小（此前为 0），媒体工具显示的文件信息因此准确。
- 使用 Mesio 引擎录制的 FLV 文件现在会记录精确的时长，不再向下取整到整秒，播放器因此能显示正确的时长，进度条末尾也与录制结尾一致。会话页面的 **录制内容** 标签页也会显示精确的时长。
- 修复使用 Mesio 引擎并开启 **修复 FLV 流** 时，直播中途重新推流（例如主播开启了直播延迟）后，FLV 录制可能变成一个超长文件的问题：播放器显示其时长为 0 秒，也不会按时长限制分段。现在录制在这类重新推流后会继续正常计时，并按设置分段。
- 使用 Mesio 引擎并开启 **修复 FLV 流** 时，若直播流未提供文件信息，浏览器播放器现在也能显示 FLV 录制文件的时长并拖动进度。
- 修复使用 Mesio 引擎并开启 **修复 FLV 流** 时，直播流在画面开始前发送多组相互冲突的设置，复制或转换 FLV 录制文件可能沿用较早的设置、而不是直播流最终采用的设置的问题。现在这类录制文件可以正常复制和转换。
- 修复使用 Mesio 引擎并开启 **修复 FLV 流** 时，若直播的计时从略早于零的位置开始，FLV 录制可能被压缩成几秒钟或音画不同步达数秒的问题。现在这类录制会从头正常播放，音画保持同步。
- 刚开播或刚下播、暂时无法播放的 Twitch 频道现在会显示为未开播，不再导致开播检测报错。Twitch 拒绝播放时，会显示 Twitch 返回的错误信息。
- 不存在的 Twitch 频道现在会显示为未找到，被封禁的频道显示为已封禁，不再在每次开播检测时报数据错误。
- Twitcasting 平台设置中的 **直播密码** 现在可以解锁带密码的直播。此前只有加在主播 URL 中的密码（`?password=...`）有效；URL 中的密码仍然优先。
- 指向已上传或已结束视频的 YouTube 链接现在会显示为未开播，而不是正在直播，不会再在每次开播检测时被重复录制。正在进行的直播不受影响。

## 工作流与文件处理

- 修复打开使用 NVIDIA（NVENC）编码的已保存重封装预设或工作流步骤时，编码预设可能被改为 Medium、下次保存时会保留这一更改的问题。现在会保留已保存的预设。
- 在预设步骤中使用**分离并编辑**时，现在总是以预设保存的设置为准。此前在步骤中显示的预设设置看似只读，但通过键盘做出的修改会在分离时被悄悄复制到步骤中。
- 撤销对已保存预设的修改后，**保存更改**按钮现在会重新隐藏。此前大多数处理器的预设仍会显示该按钮，就像还有未保存的修改。
- 预设编辑器中各处理器的名称和图标现在与工作流编辑器和任务页面保持一致。
- 重封装设置的空白输入框和预设 ID 输入框中显示的示例值现在已翻译。
- 工作流步骤库现在会列出刚刚创建或修改的工作流，不再显示之前的列表。
- 修复在工作流步骤库中使用输入法（例如拼音）输入搜索内容时，会用尚未完成的输入进行搜索的问题。
- **元数据**和**重封装**步骤开启**处理成功后删除源文件**但删除失败时，任务日志中的警告现在只显示一次，而不是两次。

## 弹幕

- 虎牙的普通弹幕现在不再记录颜色，转换的字幕和烧录的视频中会显示为白色，而不是蓝色。平台本身带颜色的弹幕仍保留原颜色。更新前录制的弹幕文件仍为蓝色。
- 会话页面变窄时（例如打开侧边栏后），**弹幕统计**的数据块会换行排列，不再挤在一行。
- 会话页面弹幕列表中的消息时间现在按应用语言而不是浏览器语言显示。

## 配置

- `API_PORT`、`ACCESS_TOKEN_EXPIRATION_SECS`、`REFRESH_TOKEN_EXPIRATION_SECS`、`REFRESH_TOKEN_REUSE_GRACE_SECS` 或 `MIN_PASSWORD_LENGTH` 的值无效时（例如输错或端口超过 65535），rust-srec 现在会在启动时停止，并提示是哪个变量有误。此前无效值会被忽略并悄悄使用默认值，服务器可能监听在其他端口，或按与配置不同的时长保留登录状态。未设置或留空的变量仍使用默认值。参见[环境变量](https://docs.srec.rs/zh/reference/environment)。
- 修复某个主播保存的设置无法读取，或含有录制器可以接受、但页面无法识别的值时，导致整个主播列表无法加载的问题。这类值包括：大小写不同或录制器无法识别的提取器名称、为 0 的离线确认次数或不足一秒的确认间隔、只设置了部分数值的重试策略、未保存格式列表的流选择，以及重试或超时为空的工作流步骤，例如来自导入的配置。录制器可以接受的值会按其实际采用的方式显示；无法读取的设置会显示为未配置。
- 修复大小写不同或录制器无法识别的提取器名称导致平台列表、模板列表或全局设置页面无法加载的问题。平台和模板中只设置了部分数值的下载重试策略、未保存格式列表的流选择，以及重试或超时为空的工作流步骤，不会再显示为未配置，也不会在下次保存时被删除。未设置的重试数值会显示录制器使用的默认值。
- 平台和模板的 **地址获取方式** 设置现在会显示已保存的选项，保存页面上的其他更改时，也不会再把 **始终使用 Streamlink** 重置为默认值。
- 添加仅 Streamlink 支持的网站上的主播时，检查现在使用 Streamlink 平台设置中 `streamlink.binary_path` 指定的 Streamlink 程序，也就是获取其直播流时使用的程序。此前总是使用 `STREAMLINK_PATH` 或 `streamlink`，因此该网站可能被判定为不支持。参见[环境变量](https://docs.srec.rs/zh/reference/environment)。
- 备份现在会保留每个平台和模板的 **地址获取方式** 选项（例如 **始终使用 Streamlink**）。此前在新安装中恢复备份时，这些选项都会被重置为默认值，重新改为自动获取地址。
- 在**备份与恢复**中导入配置后，通知渠道及其订阅、预设、工作流、代理，以及已打开的主播、模板或引擎页面，无需刷新页面就会显示导入的设置。
- **备份与恢复**中选择导入的文件大小现在以合适的单位（KB、MB）显示，不再总是以 KB 显示。

## 通知

- Webhook 渠道的超时时间现在最多为 300 秒，与 Gotify 渠道一致。服务器等待的时间从不超过这个值，更大的设置并不会生效。
- 处理队列严重积压的通知现在会显示队列已达到 500 个任务，即发送该通知的实际阈值。之前显示的是 200。
- 应用的标签页在后台时，严重事件的浏览器通知现在也会及时弹出，而不是等回到该标签页后才出现。
- 严重事件的浏览器通知现在会说明具体情况，而不是只显示“紧急”：账号登录失效或需要重新登录的通知会注明平台并说明原因；输出文件夹无法写入的通知会注明是哪个文件夹；处理队列已满的通知会说明有多少任务在排队。
- 浏览器通知无法送达时，服务器日志现在只记录推送服务的地址，不再记录能识别你浏览器的完整订阅地址。

## 认证与 API

- 修复其他网站构造的链接可能让流代理显示一个以已登录用户身份操作的页面的问题。现在流代理只转发视频、音频、图片和播放列表，并拒绝来自其他网站的请求。使用平台账号播放直播时，平台返回的更多类型的错误页面和账号数据现在会被拒绝，不再转交给播放器。
- 修复同一地址下其他端口或子域名的页面可能让网页界面以已登录用户的身份执行操作的问题。现在网页界面会拒绝这类请求。如果网页界面位于会改写浏览器访问地址的反向代理之后，并且所有操作都提示 "Request refused"，请让代理转发原始地址，或将该地址加入 `CSRF_TRUSTED_ORIGINS`（参见[环境变量](https://docs.srec.rs/zh/reference/environment)）。
- 修复向网页界面发送 `..` 这类 ID 时，可能让它执行与请求不同的服务器操作的问题。现在会拒绝这类 ID。
- 直接从服务器打开的录制文件（例如弹幕 XML 文件）不会再以网页界面的身份运行脚本。
- 登录失败时不会再把输入的密码写入服务器日志，退出登录失败时也不会再写入登录令牌。
- 登录失败时现在会显示服务器给出的原因，而不是内部服务器地址。
- 请求体格式有误（例如 JSON 无效、字段类型错误或缺少 `Content-Type: application/json` 请求头），或查询参数、URL 路径中的值无效时，现在会返回与其他 API 错误相同的 JSON 错误响应，并带有 `INVALID_JSON`、`INVALID_REQUEST_BODY`、`UNSUPPORTED_MEDIA_TYPE`、`INVALID_QUERY` 或 `INVALID_PATH` 等 `code`。此前返回的是纯文本。状态码不变。

## Web 界面

- 服务器未响应的请求现在会在 15 秒后报错（平台检测、连接测试和备份等较慢的操作会等待更久），页面不再一直等待。关闭或刷新标签页时，也会停止服务器仍在为该页面处理的请求。
- 列表、**仪表盘**或 **API 密钥**设置中的区域、日志文件列表或主播的状态检查历史加载失败时，现在会显示错误和**重试**按钮。主播、媒体产物、处理任务、预设、工作流、模板、平台和通知事件列表会保留标题栏和搜索框；**仪表盘**和 **API 密钥**设置中的区域不再一直加载或显示为空；日志文件列表和主播的状态检查历史不再只显示一片空白。无法打开的流水线、模板、平台、引擎、预设或工作流现在会提供返回所在列表的链接。
- 会话列表加载失败时会提示失败并提供**重试**，不再显示为没有任何录像。搜索或筛选没有匹配结果时，会提示没有符合条件的会话并提供**清除筛选**。
- 现在可以通过会话列表的页码翻到所有会话。此前页数按每页 50 个会话计算，而每页实际只显示 20 个，超出最后一个页码的会话无法从列表中找到。
- 会话列表现在通过页面标题栏中的**选择**按钮开启多选，并使用与其他列表相同的选择栏。各页面的空列表样式保持一致，主播卡片显示各平台自己的图标和颜色，全局设置和主题设置只在页面足够宽时才并排显示各区块。
- 在会话、媒体产物、处理任务、预设或工作流列表中删除最后一页的最后几项后，会回到上一页，不再停留在显示“未找到”的空白页。
- 媒体产物、处理任务、预设和工作流列表地址中的页码现在与其他列表一样从 1 开始计数，各处的 `?page=2` 都表示第二页。之前保存的这些列表的链接，打开的会是原来的前一页。
- 删除主播或会话时改用应用内对话框确认，不再弹出浏览器提示框；删除主播的过滤器前也会先确认，不再直接删除。
- 在模板、平台、引擎、预设或工作流编辑器中有未保存的修改时离开，会先询问是否放弃。全局设置和主播编辑器原本就会询问，现在改用应用内对话框。
- 登录状态续期时，下载、上传和检测进度不会再中断一段时间，放在后台的标签页也是如此。
- 应用的实时连接跟不上时结束的录制，不会再在主播卡片上一直显示为录制中；与服务器的连接恢复后，检测历史和主播状态会立即更新，不会再过期好几分钟。
- 在主播列表中启用、停用或批量修改主播后不久打开其页面，现在会显示修改后的设置；与服务器的连接恢复后，已打开的主播页面也会更新。
- 在会话页面中，仍在录制的会话无需刷新页面，每个分段完成后就会显示出来，时长和大小保持更新，结束时也会显示结束时间。其时长会持续增加，不再停留在打开页面时的时长。已结束的会话不再在主播头像上显示绿色的直播圆点。
- 运行中的任务页面会实时显示进度，向服务器请求更新的次数也大幅减少。
- 日志很长的任务在运行或滚动时不再让页面卡顿，只绘制屏幕附近的日志行。因此浏览器的查找只能搜到这些行，日志新增了**复制日志**按钮，可复制所有已加载的日志行；浏览器不允许复制时会改为下载文件。
- 删除任务时会在应用内弹窗确认，然后打开任务列表。此前会返回上一个页面，从链接打开任务时会离开应用。
- 已完成的任务现在会在任务页面显示输入和输出大小，此前这两项一直为空。大小会以合适的单位（KB、MB、GB）显示，不再总是以 MB 显示，标签也已翻译。
- 在**播放器**页面播放不属于任何主播的地址时，现在会按该平台的 **地址获取方式** 设置获取直播流，平台未设置时使用全局设置，例如 **始终使用 Streamlink**。此前总是使用自动方式，因此能正常录制的直播在这里可能无法播放。
- 浏览器拒绝复制时（例如通过局域网内的普通 HTTP 地址打开应用），复制文件路径、API 密钥、MCP 配置或通知事件时会提示复制失败，不再显示复制成功或毫无反应。
- 搜索框、筛选菜单、开关、滑块，以及只显示图标的按钮（例如圆形添加按钮和**清除筛选**）现在都有读屏软件可以读出的名称。会话、处理任务和通知事件页面的筛选按钮现在会说明是否已选中；此前读出时缺少名称的设置（例如 Huya 和 TikTok 的 API 模式）现在会读出名称。
- 此前只在鼠标悬停时出现的按钮（例如通知事件中的**查看详情**、工作流中的步骤按钮和**日志**设置中的移除按钮）现在在触屏上以及用键盘切换到时也会显示。**浏览器通知**或**桌面通知**卡片、模板中的平台设置区块、会话预览上的播放按钮以及会话的多选现在都可以用键盘操作。
- 中文界面中，登录、修改密码、主播、工作流、通知渠道、模板和预设等表单的错误提示现在显示为中文，不再是英文。日期选择器显示中文的月份和星期，会话页面的数字和 API 密钥的日期按应用语言而不是浏览器语言显示；启动画面、部分卡片标签、编码预设说明和读屏标签也已翻译。

## 监控与维护

- 在默认的 Docker 部署中，**系统健康**现在会按数据文件夹所在磁盘报告数据库文件夹的剩余空间，并显示为 `/app/data`。此前剩余空间取自容器自身的存储，而不是挂载的数据文件夹，文件夹也显示为 `app/data`。
- 尚未检测的组件现在在仪表盘、健康页面和存储用量条中都显示为灰色，不再在仪表盘上显示为红色、在存储用量条上显示为绿色。

## 部署与桌面端

- 网页容器的访问日志不再记录播放、下载和实时更新链接中附带的登录令牌。
- 在桌面应用中保存**桌面通知**设置时不再短暂删除设置文件，因此设置不会在保存过程中被重置为默认值。
