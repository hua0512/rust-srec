# 更新日志

## `unreleased`

## 新增功能

- **哔哩哔哩和 Twitch 批量检测：** 新增平台设置 **批量检测**，在一次请求中向哔哩哔哩或 Twitch 询问最多 100 位主播是否在直播，仍未开播的主播不再逐个检测，监控大量主播时更不容易被限流。该设置默认关闭，可以为模板或主播单独设置。代价是最多可能晚四分之一个检查间隔才发现开播；由于批量请求不使用账号，账号登录过期也可能要等到主播开播时才被发现。以这种方式得出结果的检测会在主播的检查历史中以不同样式显示。参见[批量检测](https://docs.srec.rs/zh/platforms/#batch-detection)。

## 工作流与文件处理

- 修复了 **最大上传数** 设置不起作用的问题。此前 rclone 上传只受 **最大 IO 任务数** 限制，并占用移动、复制等任务的名额，百度网盘上传则不受这两项限制，因此即使将最大上传数设为 1，仍可能同时进行多个上传。现在最大上传数同时限制 rclone 与百度网盘上传，上传也不再计入最大 IO 任务数。百度网盘上传仍逐个运行。最大上传数默认为 3，如果此前同时运行的上传多于这个数，请调高该设置。调低任一限制会立即生效；调高到超过 rust-srec 启动时的值则需要重启。
- 修复了工作流步骤自身的超时对 **execute** 步骤不生效的问题。此前命令仍会在全局 **Execute** 超时（默认 1 小时）时被终止，因此允许运行更久的步骤会提前失败。现在步骤的超时会替代该步骤的 Execute 超时。
- 修复了已取消或超时的百度网盘上传可能与下一次上传重叠的问题。此前停止的 BaiduPCS-Go 尚未退出时，下一次上传就可能开始，而两个 BaiduPCS-Go 进程同时写入其本地状态可能会将其损坏。现在下一次上传会等待已停止的进程退出，并在日志中说明；在此之前，从账号卡片登录会提示 BaiduPCS-Go 正忙。
- 修复了 rclone 上传的尝试次数超过预设“最大重试次数”的问题。此前 rclone 会在每次失败后自行重试最多 3 次，然后才进入下一次重试，因此失败的上传实际可能执行配置次数的三倍，而任务进度中看不到这些尝试。现在任务进度中显示的每次尝试都只上传一次，总次数由“最大重试次数”限制。如需恢复 rclone 自身的重试，可在预设的额外参数中传入 `--retries`。
- 修复了可以删除或重命名仍被流水线使用的任务预设或工作流的问题。全局设置、平台、模板、主播以及其他工作流中的流水线按名称引用预设和工作流，删除或重命名后这些流水线在运行时会失败。现在此类操作会被拒绝，并以对话框列出其仍在何处被使用，每项均可点击跳转；以 replace 模式导入配置时，导入后的流水线仍在使用的预设和工作流会被保留，并以警告列出。

## Web 界面

- 全局设置页现在会在调高 **最大上传数**、**最大 CPU 任务数** 或 **最大 IO 任务数** 时给出提示。调低这些限制会立即生效，但调高到超过 rust-srec 启动时的值需要重启后才生效，此前只在服务器日志中提及。
- 模板卡片现在会在 **使用情况** 中显示使用该模板的主播数量，并可跳转到这些主播。删除仍被主播使用的模板时，现在会说明无法删除的原因并提供 **查看主播** 按钮，而不再显示原始的服务器错误。
- 修复了网页界面无法识别部分服务器响应、转而显示笼统错误或服务器原始消息的问题。没有弹幕统计的场次会显示加载失败和 **重试** 按钮，而不是说明暂无弹幕统计；在播放器中刷新已过期的直播流会直接失败，而不是重新获取直播流。代理名称已被占用、已有相同地址和用户名的代理、代理已在别处被修改、站点已有账号配置等情况会显示服务器原始消息，而不是相应的说明或仍在使用它们的设置列表。此外，取消一个刚刚结束的流水线会报错，需要修改密码的会话要等到下次加载页面时才会跳转到修改密码页面，无法连接服务器时的登录错误也没有翻译。桌面应用不受影响。
- 修复了关键词过滤、直播流选择、邮件收件人等可填写多个条目的输入框在使用中文或日文输入法时会添加未完成文字的问题。此前按回车选择候选词时，已输入的内容（例如拼音字母）会被直接添加为条目。现在只有在输入法完成输入后，按回车才会添加条目。
- 修复了在主播编辑页保存、点击返回箭头或取消 **添加主播** 后，主播列表总是回到第一页的问题。现在列表会回到离开时的页码，并保留原有的搜索、筛选和排序。
- 修复了主播、流水线任务、任务预设等列表在所有项目都能在一页显示时，**每页**选择器随之消失的问题。选择更大的每页数量后便无法再改回较小的值。现在只要较小的每页数量会让列表重新分页，选择器就会保持显示。
- 主播列表默认排序时，同一状态内的主播现在按最近一次开播时间从近到远排列，而不再按优先级排列。正在直播的主播仍排在最前，出错的主播紧随其后，接着是未开播的主播，现在排在已禁用的主播之前。刚刚下播的主播不会再排到已禁用或几个月未开播的主播后面。仪表盘上的直播中主播现在也按开播时间排列。按 **状态** 排序时现在也使用同样的顺序，而不再按字母顺序排列（那样会把直播中的主播排到列表中间）。按名称排序现在不再区分大小写。
- 修复了录制会话页面的 **自定义** 日期范围遗漏最后一天的问题。此前在结束日当天开始的会话不会列出，因此只选择一天时几乎没有结果。现在日期范围包含结束日全天，只选择开始日期时会显示当天的会话。
- 修复了部分输入框未与其标签关联的问题，包括登录页和修改密码页的密码框、任务预设的 ID 和描述，以及主播名称。此前点击标签不会定位到输入框，屏幕阅读器不会读出输入框的名称和错误信息，输入无效时输入框也不会显示红色边框。
- 修复了密码管理器无法正确处理 rust-srec 密码输入框的问题。此前修改密码时，密码管理器无法得知新密码属于哪个已保存的登录信息，也无法识别哪些输入框填写的是新密码，因此可能无法保存新密码。邮件、Webhook、Telegram、Gotify 通知、直播间密码以及百度网盘登录等其他服务的密码和令牌输入框可能会被自动填入 rust-srec 的登录信息，现在浏览器不会再在这些输入框中提供该登录信息。
- 修复了手机和平板在登录页会自动将用户名首字母大写或自动更正的问题。用户名区分大小写，因此自动大写的首字母会导致登录失败。
- 修复了 **主题** 设置页中的主题模式和侧边栏选项无法用键盘操作的问题。此前无法用 Tab 键聚焦这些选项，也无法用回车或空格键选择，屏幕阅读器也不会读出当前选中的选项。
- 修复了在较小的窗口或手机屏幕上，较高的对话框会超出屏幕底部的问题。由于背后的页面无法滚动，对话框底部的按钮此前无法点到。现在对话框会适应窗口高度，并可在内部滚动。
- 修复了中文界面中时长显示为“2h 5m”等英文单位的问题，涉及录制会话和录制片段的时长、正在进行的下载时长、**系统健康**页面的运行时间、任务的平均时长，以及文件操作无响应的时长。
- 网页界面和桌面应用在录制或上传期间不可见时占用的 CPU 更少。浏览器标签页处于后台或桌面窗口最小化到托盘时，下载、上传和任务进度不再每秒刷新两次，重新显示时会立即更新到最新进度。
