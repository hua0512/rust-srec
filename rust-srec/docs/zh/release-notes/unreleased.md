# 更新日志

## `unreleased`

## 服务生命周期组织

- **启动耗时的记录聚焦初始化工作**

  容器的关闭期限、输出根辅助逻辑、事件决策和生命周期测试已按职责整理。启动日志不再记录细小的同步构造耗时，只保留 I/O、引擎发现和整体耗时。初始化顺序、输出根快照和关闭行为不变；请参阅[容器职责](../concepts/architecture.md#服务容器职责)。

## 构建依赖

- **只编译实际用到的系统信息与日志功能**

  系统信息库现在只启用 CPU、内存和磁盘支持，不再带上未使用的温度、网络接口和用户账户功能。移除了未使用的 JSON 日志格式化功能，以及对 protobuf 标准消息类型的直接依赖；代码生成所需依赖仍保留。后端依赖统一使用工作区版本，锁定的依赖包不因此升级。

## 后端模型清理

- **统一主播状态类型，移除未使用的 Rust 接口**

  数据库模型现在改用 `domain::StreamerState`。移除了未使用的数据库批量写入、配置事件合并、重复会话实体及闲置辅助方法。Rust 集成请参阅[后端接口说明](../concepts/architecture.md#后端-rust-接口)。REST 数据格式、录制行为、状态转换校验和运行时退出清理行为不变。

## 内部指标

- **监控代码反映实际可用的接口**

  移除了未使用的 Prometheus 导出器，以及未接入的下载、管道、主播和系统计数器，其中潜在的下溢和标签转义问题也一并消失。内部 Web Push 投递计数器和 JSON 健康接口继续可用；调用已移除指标 API 的 Rust 代码应改用受支持的子系统快照。

## 调度恢复

- **Actor 忙碌或配置重载时，生命周期反馈依然保留**

  「已开始」和「已结束」反馈拥有独立且有界的所有权，不再依赖进度广播。邮箱饱和时仍会保留投递；过期世代与被取代的任务不会覆盖当前调度。配置解析有界，并保留最新目标更新。接纳容量不足时请求重试，不伪造 Offline；请参阅[可靠反馈](../concepts/architecture.md#可靠的生命周期反馈)。

- **高错误计数仍遵守一小时退避上限**

  错误退避在运算前限制指数增长，避免溢出。移除了未接入运行时的 Actor 状态文件 API 和未使用的主播错误写入接口；运行时恢复、批量检测及 Actor 终止决策不变。Rust 集成请参阅[调度器接口说明](../concepts/architecture.md#调度器状态与退避)。

- **Actor 时序使用解析后的覆盖配置，周期检查分散进行**

  创建 actor 及处理主播元数据、模板、平台或全局更新时，直接解析四层配置中的离线确认参数，不再与另一元数据刷新任务竞争。周期检查加入有界的 ±10% 随机偏移；无关更新不改检查时间，真正的周期调整可提前检查，同时保持准入、冷却、智能唤醒和立即检查约束。详见[调度器时序](../concepts/architecture.md)。

- **actor 的终止决定不再触发崩溃重启**

  主播被移除等不可恢复的消息错误，现在与定时器错误一样走正常停止路径。可恢复的崩溃仍会重启，但连续十次崩溃后不再自动恢复，即使较早失败已离开退避窗口。显式移除或重置后额度重新累积；详见[重启上限](../operations/monitoring.md#调度器重启上限)。

- **关闭和禁用反馈不会上报凭空产生的下播事件**

  关闭应用或禁用主播清理时产生的调度反馈，现在只暂停本地轮询，不再上报权威 Offline 状态。这样既保留关闭时的会话恢复能力，也不与禁用流程的会话关闭操作冲突。未知的内部停止会等待真实状态检查；真正的主播下播反馈仍交给 monitor。

## 弹幕文本

- **弹幕 XML 与 MCP 分页保留有效文本**

  新写入的弹幕 XML 会过滤 XML 1.0 禁止的字符并清理头部注释。MCP 按字节分页保留完整 UTF-8 字符及后续偏移；编码无效或无法继续读取的上限返回明确错误。已有文件不会自动修复；详见 [MCP 分页](../api/api-keys-mcp.md)。

## 服务所有权

- **关闭时一并收尾会话清理任务**

  关闭时取消已结束会话的延迟清理，不再等待其保留期到期。API 构建复用容器中的仓库与配置导入服务，但保留各自独立的归档缓存。详见[服务所有权](../concepts/architecture.md#服务所有权)。

## 健康监控

- **某组件状态未知时，整体健康会降级**

  刷新后只要磁盘或其他组件的状态未知，就不再报告整体健康。不健康组件仍具更高优先级；降级实例仍保持就绪。

- **磁盘采样缓慢时健康检查仍能响应**

  系统与磁盘采样在专用线程运行，等待时间有上限。文件系统阻塞时保留旧值并标记为过时或降级，其他探针继续运行，也不会累积出替代任务。即使系统调用仍被阻塞，健康检查器也能完成关闭；详见[文件系统采样缓慢](../operations/monitoring.md#文件系统采样缓慢)。

## 下载器接口

- **FFmpeg 分片进度与收尾共享同一套实现**

  直接 FFmpeg 录制与 Streamlink 重封装现在使用同一个分片跟踪器。切换分片不再沿用上一个文件的字节采样状态；辅助任务收尾超时后，已合并的等待结果仍保留。最终文件仍须等待确认的进程收尾；输出错误与退出码 228 的优先级不变。详见 [FFmpeg 录制事件](../concepts/architecture.md#ffmpeg-录制事件)。

- **Mesio 诊断报告所链接库的版本**

  引擎检查现在报告 Mesio 编译时的包版本，不再用硬编码的历史版本。下载管理器的任务所有权、事件传递和测试已按职责整理，移除了未使用的更新、进程和配置辅助接口。现有下载事件和关闭行为不变；请参阅 [Rust 接口说明](../concepts/architecture.md#下载器-rust-接口)。

## 进程清理

- **确认完成的启动恢复会清除上一代遗留的工作**

  恢复现在会明确报告元数据加载、管道和协调器的部分失败，并分页读取全部会话分片。只有确认恢复完成，才清除上一代遗留的工作；当前所有权在干净退出前保持未清理。跨进程的记录事务防止迟到的确认覆盖新一代记录。

- **macOS 进程清理在截止时间内等待退出确认**

  进程组终止返回 EPERM 时，强制清理现在会处理主进程正在退出、但还无法回收的情况。它会用剩余清理预算确认退出（不提前回收进程），然后重试受保护的进程组终止。未确认的清理仍返回错误。

## 日志

- 应用日志现在有单文件大小和数量上限（默认 16 MiB × 16 个），共享同一目录的实例协调轮转。七天年龄清理、带序号文件的日期筛选和归档快照仍受支持。超大记录标记为截断；回收失败和紧急 panic 写入都无法绕过上限。参见[日志保留](../operations/monitoring.md#日志)。

- **日志启动与空闲行为更加可靠**

  日志文件初始化失败会返回错误，而不是触发 panic；清理服务一启动就执行保留策略；重定向的控制台输出不再带 ANSI 颜色；没有订阅者时跳过实时日志格式化。

- **日志归档在资源限制内流式下载**

  下载使用有界缓冲区流式生成 ZIP64 归档，不再把整个 ZIP 保存在内存中。最多两个并发下载，超出的请求返回 HTTP 429 并附重试等待时间。每个归档最多 10,000 个匹配的日志文件。正在写入的日志只读到扫描时的大小；中断下载会释放容量，读取或压缩失败会终止下载，而不是返回不完整的归档。不会创建临时归档文件。

## 数据库维护

- 作业与 DAG 发布、会话、媒体和分段创建现在共享完整的仓库列绑定。条件状态与结束校验、时间戳、数据库默认值、原子大小核算和回滚仍归各自调用方负责。

- **默认数据库列表页避免全表排序**

  新的启动迁移为未筛选的 DAG 和媒体输出列表添加按创建时间排序的索引，移除四个未使用的作业时间戳索引，并保留清理任务和耗时统计使用的索引。现有记录和页面排序不变；升级创建新索引时会扫描对应表。

- **SQLite 连接池共用有界的缓存额度**

  标准读写连接池现在共用 64 MiB 的建议私有页缓存额度，其中 56 MiB 分给读取连接，8 MiB 预留给写入。自适应连接池大小和 256 MiB 内存映射设置不变。连接池较大时，各连接的额度相应减少，但这不是进程内存的硬上限。详见 [SQLite 内存预算](../operations/monitoring.md#sqlite-内存预算)。

- **并发数据库操作保留各自的结果**

  并发删除同一媒体产物只会扣减一次会话大小；大小更新失败时删除也回滚。错误计数增加操作返回各自产生的计数。模板凭据刷新在同一个预留事务中读写，保留在此之前提交的配置编辑。

- **根据实际录制活动决定是否执行 Vacuum**

  定时 Vacuum 现在检查下载管理器中的实际录制数量，不再统计不存在的下载任务。录制数量超上限或准入繁忙时推迟执行；获准后暂停新录制启动，直到完成。文件系统预检查在该锁之前运行，因此缓慢的磁盘空间检查不会阻塞录制启动。轻量保留清理仍独立运行。

## 配置

- **前端编辑保留 Streamlink 的 FFmpeg 路径**

  引擎编辑器现在会保留并显示用于重封装 Streamlink 输出的自定义 FFmpeg 路径。模板覆盖可选继承引擎设置，或使用环境变量和默认可执行文件。路径文本（包括空格）原样保留。详见 [Streamlink 的 FFmpeg 可执行文件](../concepts/engines.md#streamlink-的-ffmpeg-可执行文件)。

- **导入与仓库写入共享完整字段绑定**

  全部十类导入配置及其替换、失效写入现在都由仓库统一管理。ID、时间戳、省略字段、JSON 和事务约定不变，缓存与运行时通知仍在提交后更新。详见[导入持久化](../operations/backup-restore.md#导入持久化所有权)。

- **大规模配置刷新使用有界并行查询**

  启动及全局、平台、模板更新时，最多同时刷新十六个独立主播，事件顺序和各主播的尽力处理行为不变。启动时的输出根发现结果同时用于健康检查注册和写入探测。配置优先级、待删除主播的处理和恢复确认条件不变。详见[配置刷新](../concepts/configuration.md#热重载、缓存与更新事件)。

- **备份导入会检查最终账号邮箱分配**

  导入会在修改配置前拒绝与保留账号冲突的邮箱。待更新用户之间可以交换邮箱、复用已释放的邮箱，不受导入顺序影响；后续任一步骤失败都会回滚全部改动。邮箱唯一性按存储值精确比较，包括大小写、空白、空字符串和未设置的情况。每次成功导入仍会撤销全部刷新令牌，即使合并导入省略了用户；详见[备份与恢复](../operations/backup-restore.md#配置导出)。

- **过滤器复用已解析的规则，时区边界处理一致**

  Cron 和正则定义使用有界缓存。时间规则支持显式 IANA 时区，匹配与唤醒在跨夜和夏令时切换的边界上表现一致，包括重复小时时段中重叠的窗口。两种规则省略时区或设为 null 时，都默认使用 UTC。迁移与旧版备份规范化保留现有 TimeBased 本地时间安排，显式 `local` 使用相同逻辑；同类型编辑省略时区时保留已存值，0.1.8 备份导出写明时区。两种过滤器表单都提供 UTC、服务器本地和 IANA 时区选项，编辑保留已保存的时区并显示在卡片上；新建规则和清空时区控件显式选择 UTC。详见[时区兼容性](../operations/upgrading.md#过滤器时区兼容性)。

- **代理凭据保留 URL 字符的字面含义**

  单独配置的代理用户名和密码在插入前会进行百分号编码，涵盖字面百分号、空格、Unicode 和地址分隔符。它们会替换 URL 中已有的凭据，同时保留代理主机和端口；下载启动诊断不再输出代理 URL。

- **启动输出探测使用与录制一致的写入门键**

  探测基于真实的主播/平台值和具体目录进行，使启动失败能通过录制实际使用的同一个门键阻止启动并稍后恢复。可写的子目录不再要求祖先键目录具备写权限。显式根边界优先，无法确定的模板会跳过，探测工作量有上限。探测依据已保存的设置，历史写入门条目和启动磁盘探针拓扑保持现有行为；详见[输出根探测](../operations/storage.md#输出根探测)。

- **无效配置更新会在保存前被拒绝**

  全局设置在修改任何已保存字段前，会拒绝错误的 JSON 类型、无效负数和溢出计数。自动并发、禁用录制限制和保留策略中已有的零值含义继续受支持，超时值保留原有下限处理。平台设置保持规范名称，避免编辑后无法按直播地址找到平台；数值覆盖在存储前检查范围。

- **预设和模板日期统一使用毫秒存储**

  内置预设及凭据刷新后更新的模板现在会显示正确日期。预设、模板和配置导入统一写入整数毫秒，API 继续使用日期字符串格式。新增迁移转换历史日期字符串，保留已有整数，不足一毫秒的部分直接截断、不四舍五入。无效历史值会使迁移停止，原始数据保持不变；参见[时间戳修复说明](../operations/upgrading.md#预设和模板时间戳)。

- **全新独立后端安装使用配置的录制目录**

  独立后端创建全新数据库时，会用 `OUTPUT_DIR` 初始化输出文件夹；未设置时，把 `./output` 按启动工作目录解析为绝对路径。随附的 systemd unit 和 Docker Compose 配置会提供初始录制位置。已有数据库保留已保存的文件夹，包括明确保存的 `/app/output`。

- **哔哩哔哩画质覆盖保留继承行为**

  打开继承的平台选项表单时，不再写入画质覆盖值。模板和主播表单提供「继承」选项，选择后清除覆盖。平台默认值和画质代码与哔哩哔哩提取器一致；解析器应用界面保存的模板选项，同时继续支持已有的平铺配置。

## 后处理

- **工作流在保存时即完成检查**

  保存或校验工作流时，现在会像实际运行一样解析其预设和嵌套工作流，因此缺失的预设、未知的处理器、循环依赖，或与兄弟步骤争抢文件的删除和移动步骤都会在编辑器中报告，而不是等下一次录制结束时悄悄失败。通过选项删除源文件的步骤（例如开启了 **Remove Input on Success** 的转封装）与仍要读取这些文件的步骤并列时，会在编辑器中给出警告，运行时也会写入日志。详见[自动清理](../concepts/pipeline.md#自动清理)。

- **步骤失败不再取消无关分支，删除步骤不能与兄弟步骤争抢文件**

  工作流中某个步骤失败时，只取消依赖它的步骤。其他分支上的步骤（例如与失败的缩略图步骤并行、耗时很长的字幕烧录）照常完成；工作流在还有步骤运行时显示为进行中并记录该失败，直到全部结束后才标记为失败。重试只会重新运行失败和被取消的步骤。若工作流把 `delete`、移动步骤或开启了“上传后删除本地文件”的百度网盘上传放在另一个读取同一批文件的步骤旁边，现在会在创建时被拒绝并列出相关步骤，而不是让两者争抢文件。详见[错误处理](../concepts/pipeline.md#错误处理)和[自动清理](../concepts/pipeline.md#自动清理)。

- **处理器细节：重复归档条目、烧录输出、批量大小与上传日志**

  归档步骤会拒绝两个会共用同一条目名的输入并提示使用 `preserve_paths`，不再中途失败或悄悄只保留一个。关闭透传时，字幕烧录会把未烧录的视频保留在输出中，没有弹幕的录制文件也能传到下一步。批量任务现在报告输入和输出的总大小；执行步骤的指标覆盖全部输入和输出，扫描目录无法读取时步骤会失败而不是报告没有输出。百度网盘上传不再重新发送被百度直接拒绝的文件，大批量文件会拆成多次调用以适应各平台的命令行长度限制，登录检查的账号信息不再写入任务日志；rclone 日志不再包含可能带有凭据的连接串参数。

- **字幕只在同一分段内配对，不再生成 `_inputs.json` 文件**

  配对分段和会话完成管道不再在录制文件旁生成 `session_…_inputs.json` 或 `segment_…_inputs.json` 文件，因此上传、归档、移动或删除时不会再多出这个文件。旧版本留下的此类文件已不再使用，可放心删除。每个视频对应哪个弹幕文件现在按分段随管道一起记录：某个分段没有录到弹幕时，只有该分段的视频不加字幕，后续视频不会再配到错误的字幕；前置步骤移动过文件后，字幕转换也能继续工作。转换后的字幕先写入临时文件，转换失败或超时不会再留下损坏的 `.ass` 文件。这类管道的第一个输入现在是第一个录制文件，执行步骤中的脚本可通过 `{manifest_json}` 读取配对信息。详见[管道错误处理](../concepts/pipeline.md#错误处理)。

- **Execute 编辑器支持「程序 + 字面参数」模式**

  预设和工作流内联步骤编辑器现在支持 shell 命令模式或程序 + 参数模式。每个参数都有独立输入框，保留空值、空格、引号和换行。已有命令配置仍可编辑；切换模式会清除上一模式的字段，但保留输出扫描设置。命令字段旁会说明服务器端 shell 的限制。详见 [Execute](../concepts/pipeline.md#execute-execute)。

- 媒体与传输处理器共享兼容的错误选择、结果汇总和源文件核算逻辑。输出顺序、跳过元数据、暂存与回滚以及源文件删除策略不变；命名和路径身份判断仍由各处理器负责。

- **处理器发布、路径与重试保持既定行为**

  字幕滤镜支持路径中的单引号和滤镜分隔符。关闭覆盖时，在受支持的平台上使用原生禁止替换操作；重试等待最多 30 秒、不会溢出；FFmpeg 进度统一按毫秒报告。文件检查和被放弃的临时输出清理不再阻塞异步工作线程。

- **关闭时按顺序处理已接收的管道协调事件**

  待处理的协调事件和查询会先按顺序完成，后续请求直接使用同一状态。关闭或中止协调器不再丢弃已接收的队列，回复丢失也不会导致事件重复执行。调用方仍负责执行返回的工作；取消调用方并不能保证这些外部操作完成。

- **工作流发布失败时释放待发布上下文**

  数据库发布失败时，会移除临时的分段及配对工作流跟踪信息。已成功发布的工作流保留跟踪信息，供工作线程完成后续处理。已保存预设中的无效 JSON 会在创建任务前被拒绝，校验错误不会包含配置值。

- **Rclone 移动任务首次执行时拒绝缺失的输入**

  移动任务会在开始传输前检查全部输入，首次执行时不会把缺失文件报告为已完成上传。重试任务仍可按原有方式恢复先前移动已消耗的源文件，包括同一次执行中部分传输后的重试。

- **重启恢复按已存储的视频分段匹配弹幕**

  恢复流程根据已存储的视频路径，把 XML 文件关联到原始分段索引，避免标题中的数字或媒体输出 ID 导致重复处理。找不到唯一对应分段的 XML 文件会被跳过并记录警告，不会猜测历史关联。

- **工作线程日志保留重复消息，已撤回任务不会重新执行**

  连续日志批次会保留每条记录，即使时间戳和消息内容完全相同。完成快照不会重复写入已流式保存的记录，现有日志数量限制和 API 格式不变。工作线程在执行前会检查队列是否仍持有该任务；已移除的任务不会因创建了替代取消令牌而继续运行。

- **短录制、少见音频编码和部分上传失败的处理更稳妥**

  录制时长短于所请求时间点时，缩略图步骤不再让整批任务失败，而是改用第一帧；完全取不到画面的录制会原样传递。不重新编码地提取音频时，文件名会按实际音频类型命名（`.mp3`、`.opus`、`.ogg`、`.flac`、`.wav`，其他情况用 `.mka`），不再一律使用 `.aac`，此前 Opus、Vorbis 和 MP3 源会因此失败。复制和移动步骤会拒绝两个会落到同一文件名的输入，而不是悄悄只保留最后一个；任务在传输中途被取消时会清理临时副本；跨磁盘移动的判断也更可靠。rclone 移动或百度网盘上传中途失败时，已传输的文件会记录为已上传而不是失败；rclone 现在可以在一个步骤中上传来自不相关文件夹的文件；百度网盘步骤会在上传前拒绝文件名相同的两个输入。执行步骤的输出扫描目录支持占位符，只把命令开始后创建的文件算作输出；文档也不再建议使用在工作流中为空的 `{output}`。

- **重试工作流不会再卡住**

  重试现在会先检查每个要重新启动的步骤，再修改任何数据；如果重新启动中途仍然出错，工作流会带着原因再次标记为失败，可以继续重试，而不是一直显示为运行中。被取消但从未创建任务的步骤所在的工作流，以及在应用停止期间任务已失败的工作流，现在也都可以重试。上一步没有传来任何文件的步骤（例如上传已把文件全部移走之后的删除步骤）现在会自行完成，不再导致工作流失败（执行步骤仍会运行其命令）；已被并行恢复流程调度过的步骤也不会再让工作流失败。

- **重试工作流后结果会正常交付，处理了一半的步骤不再算作成功**

  录制工作流失败后重试并在一小时内成功时，其成功结果曾被忽略，后续工作流会继续使用原始录制文件而不是重试后的结果。现在重试后的工作流会正常交付结果。只处理了部分文件的步骤（例如移动时有一个文件无法传输）此前会按全部成功完成，失败因此无人察觉，后续步骤（包括录制结束后的工作流）只能看到已处理的那些文件。这类步骤现在会失败，错误信息列出每个失败的文件，已完成的部分会保留。重试复制或移动步骤时会接着上次的进度继续：目标位置已有的文件不会再次传输。批量 remux 任务会先把全部输出写入临时文件再一起发布，中途失败或取消不再留下部分已发布的输出，某个输出也不会再覆盖同一任务中的另一个输入。

- **Execute 任务可以不经过 Shell 直接运行程序**

  执行处理器支持 `program` 和可选的 `args` 数组。每个参数只展开一次占位符，空格、引号、空值和 Shell 特殊字符都作为原始数据保留。已有的 `command` 配置继续受支持。两种模式共用超时、进程清理及输出扫描逻辑；混合配置以及程序模式下的 Windows 批处理文件会被拒绝。

- **任务运行期间降低工作线程上限也会生效**

  降低 CPU 或 I/O 并发数后，后续任务立即按新上限准入。已准入的任务可正常完成，释放的容量遵循最新上限，无需再次修改设置。快速调整上限或取消任务不会留下过期的许可预留。

- **工作流编辑保持依赖关系和预设警告准确**

  两种工作流编辑器在重命名步骤时都会更新依赖它的步骤，并拒绝空白或重复的 ID。标签和转换后删除检查按名称精确解析引用的预设，不受预设数量限制。内联步骤显示自身的处理器。加载中、加载失败或缺失的预设会明确提示；保存可能执行删除且预设尚未解析的步骤时需要确认。

- **未完成的输出不再替换完整文件**

  缩略图、提取的音频、写入元数据后的副本以及字幕烧录现在先写入临时文件，确认输出存在且非空后才发布。批量任务失败或取消时会清理暂存文件，并保留源文件和已有目标文件。发布失败时会回滚同批次中已发布的输出。指向源文件的别名路径会被拒绝；关闭覆盖时，即使多个任务同时发布到同一目标，也不会覆盖已有文件。

- **取消或超时的命令会停止其子进程**

  后处理任务取消或超时时，现在会停止整棵进程树。命令的标准输入会关闭，输出会持续读取并受日志大小限制，父进程退出但后代进程仍持有管道时也不会卡住。音频探测同样使用这一清理机制。

## 邮件投递

- 邮件渠道现在保留 SMTP 连接池，每条消息只渲染一次本地化内容。替换配置使用独立连接池，已接收的投递任务仍使用原渠道。移除了未使用的 `EmailConfig.batch_window_secs` 字段，现有 JSON 中的该值会被忽略，不影响加载。邮件仍立即发送。

## 通知

- **渠道共享统一规则，同一次投递内语言保持一致**

  外部渠道统一使用启用状态、优先级过滤和默认启动测试。同一次投递中，相同语言的接收渠道复用已渲染的标题和正文。渠道重载、事件映射、重试和 Web Push 工作各自独立，现有自定义 Rust 渠道实现仍受支持。详见[通知接口](../concepts/notifications.md#后端通知接口)。

- **有界队列与一致的 Web Push 持久化状态**

  普通渠道的准入会原子地执行容量限制，并取消被移除通知的重试；熔断冷却不额外消耗尝试次数。Web Push 首次请求成功也会清除已保存的退避状态；失效订阅删除失败不会误报成功；精简负载同样执行字节上限。详见[投递约定](../concepts/notifications.md#队列与-web-push-投递)。

- **Web Push 过载时保持资源有界**

  推送队列满或不可用时，会丢弃新事件，不再创建回退任务。所有优先级均采用 FIFO 入队策略；被拒绝的推送会计入通知统计，且不会自动重放。事件历史与普通渠道送达独立继续；详见[送达行为](../concepts/notifications.md#送达行为)。

- **配置渠道保留发送失败的通知**

  通知重试耗尽后，即使渠道来自配置，也会保留在内存死信列表中。数据库渠道仍可持久化死信；持久化失败不会丢失内存记录。保留期限清理继续生效，重试期间不会向已成功的渠道重复发送同一通知。

- **通知重载保留熔断状态与送达目标**

  重载期间，渠道与订阅查询看到的是同一份完整注册表。仍处于加载状态的数据库 ID 保留熔断历史，读取失败保留原注册表，发现期间新增的动态渠道也会保留。已接收通知在发送与重试时继续使用选定的渠道实例；移除后重新添加会获得隔离的新一代熔断器。

- **通知发送在限定时间内结束，且不会泄露凭据**

  Discord 和 Telegram 请求现在会在 30 秒后超时。Gotify 和 Webhook 的超时上限为五分钟，设为零时使用默认的 30 秒。限流重试每次最多等待 30 秒、最多三次；无效的重试延迟不再导致崩溃。发送错误保留失败类别或 HTTP 状态码，不再暴露含令牌的 URL 或服务端响应正文。

- **Telegram 格式化保留动态内容原文**

  HTML、Markdown 与 MarkdownV2 配置现在使用显式格式实体，主播名、标题和错误中的特殊字符不会破坏消息解析。Unicode 安全截断保持格式范围有效。空模式发送纯文本；未知模式返回本地配置错误。

## 录制引擎

- **Streamlink 支持显式指定 FFmpeg 可执行文件**

  通过可选的后端引擎字段 `ffmpeg_path`，可以指定 Streamlink 重封装使用的 FFmpeg 可执行文件。省略该字段或设为 null 时，仍依次使用 `FFMPEG_PATH` 和 `ffmpeg`。详见[引擎配置](../concepts/engines.md#streamlink-的-ffmpeg-可执行文件)。

## 录制

- **自定义输入不会破坏录制文件名与事件跟踪**

  主播名、标题及实际输出目录中的百分号保持字面含义，配置中的日期标记仍会展开，启动探测也遵循相同规则。FFmpeg 必需的 info 日志和统计会覆盖静默选项；较长的标准错误记录按增量扫描；下载快照只复制公开字段。

- **并发弹幕停止请求共享采集器完成结果**

  停止调用方和替代会话等待同一个采集器的结果，不再消耗其他调用方的完成信号。等待启动串行锁和旧采集器共用十秒的交接预算。调用方取消或超时不会丢弃完成结果，也不允许新旧采集器重叠；连接建立仍遵循原有的独立行为。

- **Streamlink 协作排空已接收的录制数据**

  经过认证的协作组件会停止已审计的 Streamlink 8.5.0 读取器继续采集，同时让已接收的数据、缓冲、嵌套封装器和标准输出继续排空到 FFmpeg；隐藏的 Windows 录制进程也使用相同的控制通道。只有同一进程截止时间内确认 EOF、转发成功且封装器自然完成，才确认排空；关闭期间缩短的期限也会立即生效。插件、清晰度、认证和代理选项继续可用；不透明的可执行文件和不支持协作排空的读取器保留录制行为，但不声称支持协作排空。强制或无法验证的停止会明确报告未完整排空；详见[停止 Streamlink 录制](../concepts/engines.md#停止-streamlink-录制)。

- **引擎解析的探测时间有上限，无效配置会明确报错**

  自定义引擎解析和引擎测试现在会异步探测可执行文件，探测限时三秒，并执行有时间上限的进程清理。探测输出持续读取，内存使用量有界。仓库访问失败、基础配置损坏和无效覆盖会明确报错，不再静默采用默认值；不存在的命名配置保留原有的回退行为。同步的启动构造函数也使用同一套有界探测。

- **停止录制时保留已确认的最后分段**

  FFmpeg 的优雅停止期限耗尽后，会获得一段独立且有上限的进程清理时间；Streamlink 则在共享进程期限内预留进程约束和重封装收尾时间。已确认的最后分段会在录制结束前发布一次；未确认清理成功时，不会宣告分段完成。必需的最终事件保留所有权直到被消费。未使用的 FFmpeg 标准输出不再堵塞无人读取的管道；在首个 HLS 分段出现之前停止 Mesio，也不再计为引擎故障。

- **重启后正确核对录制会话**

  首次确认下播的检查会结束上一个进程遗留的未完成会话，使最终后处理能够恢复。失败或被抑制的检查仍可重试。仍在直播的场次会继续使用原有会话，正常下播宽限期保持有效。

- **并发会话事件保留唯一的结束结果及原因**

  开播检查、下播检查、下载完成、定时器和用户停止操作现在按主播串行更新会话。延迟或重复的事件不会覆盖已结束会话的结束时间，也不会重复发布完成事件；旧会话的下播信号不会停止正在直播的新会话。禁用主播时会保留权威的下播原因；即使定时器句柄缺失，活跃会话仍能正常结束。

- **输出写入失败时可靠地暂停录制重试**

  即使直播连接同时断开，收尾时缓冲数据写入失败的信息也会保留。磁盘已满、只读文件系统、权限不足、路径缺失和输出超时，会先通知输出目录检查机制，再发布录制失败结果。FFmpeg 和 Streamlink 即使以零退出码结束，也会保留已识别的输出错误。输入网络错误不会把存储标记为不可用；未配置输出目录检查机制时，重试限流仍会保留。

- **删除主播会等待所有录制的后处理完成**

  较新的录制结束时，较早的录制可能仍在进行后处理，删除主播会使这些任务失去重启后继续处理所需的信息。现在会等待所有尚未完成的录制。未能启动的最终后处理保持待处理状态，并可在缺失的预设恢复后重试。

- **替换导入会保留正在收尾的录制所需的配置**

  当替换导入的备份同时缺少某个主播及其模板时，导入可能失败并回滚。现在，未被导入的模板和预设会暂时保留在列表中，并附上导入警告，直到正在移除的主播完成录制后处理。编辑保留的配置、重新导入它，或将保留的模板分配给活跃主播，都会取消其待删除安排。

- **共享的平台登录不再同时刷新**

  多个录制共享同一登录时，可能同时刷新凭据并错误地提示需要重新登录。现在刷新会依次进行，等待中的录制会收到更新后的 Cookie。

- **停止应用时录像可以正常收尾**

  停止 rust-srec（Ctrl+C、`docker compose down`、重启容器或关机）可能会让录像半途中断。录制程序有时会在写完文件之前就被结束，导致最后一段被截断、没有出现在场次的文件列表里，或者缺少对应的弹幕文件。现在关闭时会先停止接受新任务，等已经在录的内容收尾并保存完毕，然后才真正退出。录制程序现在也与应用本身绑定，应用退出后不会再有残留进程。

- **关闭过程一定会在限定时间内结束**

  以前某个无法收尾的录像可能会让关闭过程一直无法结束。现在有了期限（默认 30 秒），到时仍未结束的工作会被终止，应用照常退出。如果你的录像通常需要更长时间收尾，可以调大 `RUST_SREC_SHUTDOWN_TIMEOUT_SECS`；Docker Compose 文件中也配了对应的 `stop_grace_period`，好让 Docker 等待应用而不是先把它杀掉。若关闭超出了宽限期但仍完整保存了全部内容，则按正常退出处理。参见[配置](../getting-started/configuration.md#关闭)。

- **中断的关闭会在下次启动时提示**

  如果应用是被强行结束的，或者没能在限定时间内完成收尾，这一情况会被记录下来并在下次启动时提示，让中断的录像可见，而不是悄无声息地留下残缺文件。

- **保存失败不再终止正在进行的录像**

  以前只要录像的某一段写入数据库失败，整场录像就会停止。现在录像会继续，失败会被单独报告。

- **修复 FFmpeg 分段录制的 Unicode 文件名问题**

  FFmpeg 录制与后处理不再把整个子进程强制设为 `C` locale。该覆盖在 Windows 上可能导致 Unicode 输出路径无法打开，尤其会影响分段模式中通过 `strftime` 展开的文件名。消息和数字格式仍保持稳定以供进度解析，而字符与时间处理会保留父进程的 UTF-8 locale。

- **主播在监控意外失败后仍会被继续监控**

  以前主播的监控一旦遇到意外的内部错误，就会悄无声息地停下来，直到重启 rust-srec 才恢复，期间的开播都不会被录到。现在监控会自动重新启动。快速禁用再重新启用某个主播，也不会再出现重复监控或彻底失去监控的情况。

- **为单个主播保存的登录不再丢失**

  扫码为单个主播登录 B 站后，该账号只保留到下一次改动这个主播为止。重命名、启用或停用、调整优先级或加入批量操作，都会让该主播重新变回未登录状态，之后的录制也不再使用该账号。为单个主播续期的登录也是如此。无论是自动续期、手动点击刷新，还是平台在开播检测时新发放的会话，都会被丢弃。现在这些登录都会被保留。

- **磁盘写满时会直接告警，而不是让每场录像悄悄失败**

  以前录制途中磁盘写满，内置录制器只会把它当成一场出错的录像并算到该主播头上，而其他主播仍会一个接一个地以同样的方式开始并失败。现在磁盘空间不足会被正确识别。你会收到「输出路径无法写入」通知，录制会暂停，空间释放后 30 秒内自动恢复。

- **删除主播不再清空录制历史**

  以前删除一个主播，会连同它录过的所有场次一并抹掉，附带的文件列表、分段和弹幕统计也一起消失。录像文件其实还在磁盘上，但在应用里再也找不到。现在主播被删除后，过往场次仍会保留在列表中，并沿用录制时的名称显示；如果当时还有正在录制的场次，也会被正常结束，而不是一直显示为直播中。

- **删除主播时会先干净地停止录像**

  以前删除主播会在录像仍在进行时立刻移除它，于是最后一段录像可能以报错结束，场次时间线残缺不全，后处理还可能因为主播已不存在而失败。现在删除会立即把主播从列表中移除，同时先把录像正常收尾。录像被关闭并保存，后处理完成后才真正删除该主播。如果后处理仍在进行，主播会立刻从列表消失，并在后处理结束后于后台清理完毕，即使中途重启也是如此。所有删除方式都适用。这包括删除按钮、批量删除、API，以及导入一份不再包含该主播的配置。

  如果你用脚本操作，有一点需要注意。在被删除的主播完成清理之前，它的地址仍处于占用状态。此时用同一地址重新添加主播、或导入仍包含该主播的配置，都会提示「正在移除中，请稍后重试」，直到清理完成为止。删除一个仍在移除中的主播所使用的模板，也会以同样的方式被拒绝。

- **导入配置不再影响正在进行的录像**

  以前导入备份会把所有正在直播的主播短暂标记为离线，于是又推送一条「开播」通知，主播状态也会在面板上来回跳动。现在正在直播的主播保持直播状态，录像照常继续。导入文件中新增的主播也会立即开始监控，不必等到下次重启；导入被拒绝时也不会再停止任何东西。

## 认证

- **退出登录和修改密码会使已签发的访问令牌失效**

  登录令牌和刷新令牌现在共享一个持久化会话。单次退出只关闭该会话；退出全部会话，以及配置的刷新令牌重用检测，都会撤销该用户的所有会话。修改密码会原子地撤销已有会话，禁用账号后旧会话不会恢复，成功导入配置也会撤销登录会话。下载/日志 WebSocket 每五秒重新验证一次，每次查询最多等待三秒；一次性日志归档授权会重新检查其签发身份。升级后，未绑定会话的旧访问令牌需要通过仍有效的刷新令牌续期，或重新登录。详见[会话安全](../operations/security.md#可撤销的登录会话)。

- **登录失败响应隐藏账号存在性及禁用状态**

  未知用户会执行有界的模拟 Argon2 验证，并返回与错误密码相同的凭据错误。只有密码正确时才返回账号已禁用。登录限流仍先于密码验证工作执行。

- **刷新令牌原子轮换并拒绝重放**

  每个刷新令牌最多签发一个替换令牌，数据库写入失败时保留原令牌。重放尚未关闭会话中已消耗的令牌，现在默认会撤销该用户的全部访问和刷新会话；重放已经退出的会话不会使其他设备退出。可选宽限期只抑制该吊销行为，不再为重放请求签发令牌。客户端必须串行刷新；配置与并发行为详见[刷新令牌轮换](../operations/security.md#刷新令牌轮换)。

## API 与集成

- **媒体文件可以按下载方式获取**

  在媒体文件内容请求上加上 `download=1`，即可按录像文件名作为下载附件返回，而不是在浏览器中直接展示。

- **创建响应和 OpenAPI 与运行中的接口一致**

  资源创建以及模板、任务预设克隆现在返回文档所述的 201 状态，JSON 响应体保持原有结构。OpenAPI 已包含会话分段、模板克隆及浏览器 Web Push 的全部四个操作。任务摘要使用 `null` 表示不可用的进度，不再填入虚假的零；专用进度接口仍会在有快照时返回实际数据。详见[响应约定](../api/index.md#创建响应与任务进度)。

- **任务列表和配置导出批量查询关联数据**

  主播显示名称、导出的过滤器和通知订阅现按每批最多 500 个去重实体查询，不再逐个实体查询。响应/导出顺序、实体不存在时的行为及关联数据失败时的尽力处理方式不变；失败批次会逐个实体重试。详见[配置导出](../operations/backup-restore.md#配置导出)。

- **搜索按字面匹配百分号和下划线**

  任务、会话、媒体产物、通知事件及两类预设的搜索不再把 `%` 和 `_` 当作通配符，反斜杠也按字面匹配。因此 `audio_extract` 只会查找该文本，不会匹配 `audioXextract` 之类的名称。原有大小写匹配方式、其他筛选条件、分页总数和媒体汇总不变；详见[搜索筛选](../api/index.md#搜索筛选)。

- **API 错误和批量请求具有明确边界**

  内部诊断信息不再混入临时拼接的 API 错误消息中。解析与会话删除批次超过 100 项时，会在开始处理前拒绝。新登录、旧会话刷新及诊断中的设备描述最多保留 256 个 Unicode 字符；凭据刷新保留重新登录提示。

- **配置读取使用一致缓存，缺失实体使用结构化错误**

  流代理和解析请求复用五秒全局快照；应用写入与导入立即使其失效。管理读取仍直接获取最新数据，过期缓存不会掩盖刷新失败。平台、模板和引擎接口使用错误类型区分实体缺失与数据库错误，不再匹配消息文本。

- **支持通过 API 密钥进行程序化访问**

  现在可以创建长期的 API 密钥，作为短期 JWT 会话令牌之外的另一种认证凭据。密钥归属于创建它的用户，支持设置可选的过期时间，并可配置 `read_only`（只读权限，仅允许查询录制会话、弹幕、聚合统计、通知事件及系统健康状态等非敏感信息）与 `full`（完全权限，可执行包括修改配置在内的所有操作）两种权限级别。服务端仅存储密钥的 SHA-256 哈希值，原始密钥仅在创建时展示一次。吊销密钥会立即在服务端生效并清除认证缓存。API 密钥无法用于管理其他密钥或修改密码。只读密钥可读取需要认证的健康详情和录制媒体；下载/日志 WebSocket、流代理和日志路由需要完全权限密钥。这些手动认证路由优先使用 Authorization 请求头，只有缺少请求头时才回退到查询参数令牌。详见 [API 密钥与 MCP](../api/api-keys-mcp.md)。

- **内置 Model Context Protocol (MCP) 服务器**

  后端在 `/api/mcp` 端点内置了基于 streamable HTTP 传输协议的 MCP 服务器。Claude Code、Claude Desktop、Cursor 等 AI 助手可以通过 API 密钥直接接入，执行查询录制会话、分析弹幕活跃度与词频、按字节分页读取原始弹幕 XML、监控管道任务、管理主播及更新系统配置等操作。所有 MCP 工具均在后端进程内直接调用对应服务，使用与现有服务相同的数据校验与热更新能力。只读密钥被严格限制在安全查询工具内，无法读取任何配置或已存凭据。详见 [API 密钥与 MCP](../api/api-keys-mcp.md)。

- **Web 界面提供独立的 API 密钥管理**

  在 **设置 → API 密钥** 页面中，可以便捷地创建、查看与吊销具有自定义名称和有效期的 API 密钥。页面还提供一键复制适用于 Claude Code、Cursor 及标准 MCP 客户端的配置片段。

- **登录失败过多会被限速**

  密码不再可以无限次数地猜。同一账号连续五次登录失败后会进入一段冷却时间而被拒绝，返回内容会告知需要等待多少秒。登录成功会立即清零计数，提示信息也不会透露用户名是否存在。另有一个宽松得多的配额限制单个来源能消耗多少密码校验开销；需要注意的是，在反向代理（包括 rust-srec 自带的前端）之后，所有登录看起来都来自代理，因此该配额是在保护服务器，而不是区分不同用户。密码校验现在也会排队执行，大量登录请求不再拖慢应用的其他功能。两个配额均可通过 `API_LOGIN_MAX_FAILURES`、`API_LOGIN_IP_MAX_FAILURES` 和 `API_LOGIN_WINDOW_SECS` 调整。详见[配置](../getting-started/configuration.md#登录限流)。

- **关闭登录时收紧了浏览器访问范围**

  在不需要登录的本地开发模式下，后端以前会接受任意网站发来的浏览器请求。现在，来自未知页面的请求，以及使用本机地址之外的网址访问的请求，都会被拒绝，同一浏览器里的其他标签页无法再悄悄向录制程序发指令。本地 Web 界面、桌面端以及 `curl` 之类的工具不受影响。如果你从其他地址打开界面，请在新增的 `API_CORS_ORIGINS` 选项中列出它。开启登录时行为不变。此时保护 API 的是密码或 API 密钥。详见[配置](../getting-started/configuration.md#安全与认证)。

- **使用 `DELETE /api/pipeline/{pipeline_id}` 取消管道现在会真正结束它**

  该请求只会停止管道中的步骤，管道本身却一直显示为处理中。无法重试，重启后依旧如此，对应录像的后处理也永远走不完。现在它会一并结束整个管道，可以重试，录像也能继续。只有直接调用该请求的脚本和集成受此影响。Web 界面上的**取消**按钮使用的是另一个请求，一直都是正常的。

## 管道与上传

- **共享处理器驱动并保留发布策略**

  输出规划、四种媒体驱动、九种单文件跳过结果及路径解析机制现在共享实现，同时显式保留命名、映射、发布和身份判断策略。所有媒体驱动共用同一套暂存发布机制，详见[处理器约定](../concepts/pipeline.md#处理器结果约定)。

- **管道完成与恢复共享产物处理逻辑，并减少查询**

  管道构建、输入清单、叶子输出收集和源产物启动预留现已使用共享实现。DAG 发布时仅查询一次主播来获取名称和平台；完成处理复用事务内的记录快照；恢复则一次分页扫描会话的全部状态。清单结构、输出顺序、可选元数据、写入失败报告和重复完成保护不变；详见[管道错误处理](../concepts/pipeline.md#错误处理)。

- **重试保留执行历史和先前发布的文件**

  开始新的尝试不再重置步骤耗时、日志计数、文件大小信息或产物历史。以前的日志不会被重复写入，完成和失败更新也会保留额外的已存储执行信息字段。处理器仅在执行标记保存后运行；信息无效或保存失败时会停止处理并报告失败，不会替换原始信息。重试失败不会删除先前尝试已发布的文件，处理器仍负责清理自己的暂存临时输出。

- **重试工作流不再让已取消的分支卡住**

  只重试失败工作流中的单个任务，可能使其他分支一直无法完成。现在工作流任务会提示重试整个工作流，让失败和已取消的分支一起重新启动。

- **支持把录像上传到百度网盘**

  新增 `baidupcs` 管道处理器，通过 BaiduPCS-Go 命令行工具把录像上传到百度网盘，Docker 镜像已内置该工具。像其他上传步骤一样加进管道即可。目标文件夹支持主播、标题、日期等占位符，同名文件可以跳过或覆盖，上传的实时进度、逐文件记录和主播卡片上的上传状态与 rclone 完全一致。登录直接在预设编辑器里完成。粘贴一次网盘 Cookie（或 BDUSS 和 STOKEN），账号卡片就会显示当前账号和剩余空间。勾选**记住凭据以便自动重新登录**后，登录会话过期时上传任务会自行重新登录，半夜录完的直播照样能上传进网盘；不勾选则凭据只交给 BaiduPCS-Go，应用本身不保存。如果记住的凭据本身失效了，会收到一条提醒通知，后续尝试也会暂停一小时，不会反复请求百度。退出登录会一并清除记住的凭据。由于 BaiduPCS-Go 的退出码无法反映上传结果，rust-srec 会解析它的逐文件输出来判断是否成功，重试任务时只重传没有成功的文件。详见 [DAG 管道](../concepts/pipeline.md#百度网盘-baidupcs)。

- **崩溃后的后处理不再卡住或重复执行**

  如果应用意外停止（崩溃、主机重启、容器在任务执行途中被结束），某场录像的后处理可能停在一半。剩余步骤再也不会启动，场次一直显示为处理中且无法重试；与此同时，刚刚完成的步骤可能在下次启动时再执行一遍，把已经上传过的文件重新上传，并重新执行其后的移动或删除步骤。现在后处理会从中断的地方继续，已经完成的步骤不会重复执行。

- **无法执行的管道步骤不再阻塞整场录像**

  如果某个步骤指定了并不存在的处理器，它会被正常保存并排入队列，然后永远不会被取走执行。管道一直停在「处理中」，对应录像的后处理永远走不完，卡住的任务还会一直计入队列长度，最终导致应用限制自己的录制。内置的**创建 ZIP 压缩包**预设，以及在预设编辑器里创建的压缩类预设，都属于这种情况。它们指定的处理器名称是工作线程无法识别的。现在这些预设可以正常执行了。若管道仍然指定了未知的处理器，保存时就会被拒绝，并列出可用的处理器；此版本之前已经卡住的任务会在启动时置为失败，让等待它们的录像能够继续。

- **管道任务开始、完成与失败的通知现在会送达**

  订阅**管道开始**、**管道完成**或**管道失败**后收不到任何消息。转码或上传失败也不会有通知发出。现在这些通知会随任务执行正常触发。

- **删除管道执行记录会一并停止其正在进行的工作**

  删除仍在运行的管道只会把它从列表中移除，任务却还在后台继续。转码或上传照常进行，而对应录像会一直等待一个已经不存在的管道。现在删除会先取消正在进行的工作。

- **超时的任务会说明当时在做什么**

  转码或上传超过任务时限时，任务记录和通知里都只有一句「Job timed out」。现在还会写明超出的时限、卡住的是工作流中的哪一步和哪个工具、当时正在处理的文件，以及最后一次上报的进度和距今多久。看一眼通知就能分清是传输卡死还是本来就慢。

- **排队的任务按先进先出执行**

  当排队的任务多于工作线程的处理能力时，每次都会优先取走最新加入的任务，较早的任务可能被无限期地跳过，新录像不断插队。现在同优先级的任务按入队顺序执行；优先级更高的仍然优先。

- **转码不再删除自己刚生成的文件**

  开启「成功后删除输入文件」时，如果输出实际上和输入是同一个文件（例如通过符号链接的目录访问，或在 macOS 与 Windows 上仅大小写不同），该步骤会先用转码结果覆盖原录像，随后又把它删除，两者都会丢失。现在步骤会识别出输入与输出是同一个文件并予以保留。

- **移动步骤不再为并未移动的文件报告成功**

  移动步骤发现源文件不存在时，只要目标文件夹里存在同名文件，就会被当作「此前已经移动完成」的证据，并把这个无关的文件传给后续步骤。现在该续传逻辑只在其本来适用的场景生效。重试的任务，或崩溃后重新执行的任务。

- **工作流的输出以固定顺序传给下一个步骤**

  位于工作流之后的步骤，每次运行收到的工作流输出顺序都不相同，这会改变合并类步骤（如拼接）的结果。现在顺序按工作流定义的顺序传递。

- **关闭应用时不再等待耗时的后处理任务**

  关闭时仍在执行的转码或上传会让应用一直等到关闭期限耗尽、所有工作被强行终止，并被记为非正常退出。短任务仍然会得到完成并记录结果的时间；耗时较长的任务现在会被提前要求停止，让应用正常退出，该任务会在下次启动时从头执行。

- **从未启动的后处理现在会被补上**

  如果应用恰好在录像结束、后处理尚未建立的那一刻停止，或者建立过程本身失败了，这部分工作就彻底丢失了。配置为录制结束后运行的上传、转码等步骤根本没有执行，而且没有任何提示。现在启动时会发现这类应当执行却从未开始的后处理并将其启动，无论应用停了多久都能补上，整场录像和单独某一段录像都适用。此版本之前就已完成的录像不受影响，因此升级（或首次开启后处理）不会追溯地对已经录好的全部内容执行一遍。

- **可以一次选中多个管道批量操作**

  清理已经结束的管道只能逐个打开卡片菜单、逐个确认。**管道任务**页面现在有了**选择**按钮。勾选需要处理的管道，即可一次性取消、重试或删除。重试和取消只会作用于状态允许的那些管道，按钮上会显示本次会影响其中多少个；删除则对任意状态都有效，仍在运行的会先被取消。如果批量操作中有一部分没有成功，只有这些管道会保持选中，方便你单独重试。

- **可以在媒体产物页面删除录制文件**

  媒体产物此前只能浏览，想腾出空间就得自己去磁盘上找文件，而且删完之后也没有办法清理残留的记录。现在每个产物都有**删除**选项，**选择**按钮还支持一次清理多个。默认只会删除记录、保留磁盘上的文件；如需连同录像文件一起删除，请在确认框中勾选**同时从磁盘删除文件**。如果文件此前已被你手动删除，删除记录同样可以正常完成，并且无论哪种方式，所属录像的总大小都会被同步修正。

- **Execute 模板在启动前检查占位符用法**

  Execute 会在启动前拒绝不支持的占位符上下文。program/args 及不含已识别占位符的模板保留原有行为。含占位符的模板支持普通参数、重定向和文档列出的 Shell 运算符；Windows 要求使用原生程序，采用常见 C/Shell32 参数编码，并检查 cmd 的长度限制。不支持的形式请改用 program/args 或具有明确数据接口的固定脚本；自定义参数解析器必须接受所传入的编码。支持的语法及迁移方式见 [Execute](../concepts/pipeline.md#execute-execute)。

- **重启后重新排队的任务不再显示过时的进度**

  如果应用在转码或上传执行途中停止，该任务会在下次启动时重新排队，但进度仍停留在停止前的百分比。一个只是在排队等待的任务可能一直显示「42%」，直到它真正重新开始执行。现在任务回到队列的那一刻，旧的进度就会被清除。

- **大体积录像现在可以打包成 ZIP**

  超过 4 GB 的录像在打包 ZIP 时会失败。压缩包写到一半就被放弃，最终什么也没有留下。现在任意大小的录像都能正常打包。

## 弹幕

- **弹幕录制不会因网络中断而停止**

  以前如果与平台弹幕服务器的连接断开、且几分钟内无法重连，弹幕录制就会在本场直播剩余时间内彻底停止。视频照常录制，但后面的每一段都没有弹幕文件，而且没有任何提示。现在只要录制还在继续，弹幕就会一直尝试重连，网络恢复后自动重新连接。即使某一段录制期间连接是断开的，这一段仍然会生成自己的弹幕文件，统计也会接着之前的数字继续累加，而不是从零重新开始。持续断开的弹幕连接会在系统健康页面上报出来，不再是静默故障。

- **弹幕录制失败不再卡住后续处理**

  弹幕录制意外结束时，该场次的后续处理步骤（上传、转码等所有配置为录制结束后运行的步骤）都不会被启动。现在它们会正常执行。

- **直播最后的弹幕不再丢失**

  录制停止时，平台已经发出但仍在队列中的弹幕会被丢弃，最多可达本场最后一百条，统计和最后一个弹幕文件里都没有。现在会在录制收尾前先取回这批弹幕。

- **弹幕不再混入下一段录制**

  过去分段录制切换时，上一段结尾积压在队列里的弹幕会出现在新的一段开头；现在已修正逻辑，这批弹幕会正常留在上一段。

- **弹幕文件不再残缺**

  因连接故障结束的弹幕录制会留下一个未正常收尾、也未登记的文件，它既不会出现在场次的文件列表里，也无法被弹幕转换步骤使用。现在文件会被正常收尾并像其他文件一样登记；如果某段录制因体积过小被丢弃，对应的弹幕也会一并从场次文件列表中移除。

- **弹幕统计可按主播配置**

  弹幕活跃度的汇总方式不再固定。全局配置新增**弹幕统计**分区，平台、模板和主播三层均可覆盖。可设置排名的发言人和高频词数量、活跃度时间线的精度、计数转为估算值前跟踪的不同发言人数，以及高频词图表中额外忽略的词。也可以完全关闭统计而仍然录制弹幕文件，从而不保存观众昵称。详见[配置](../getting-started/configuration.md#弹幕统计)。

- **高频词计数不再虚高**

  在弹幕密集的直播中，高频词图表可能给出远高于真实值的计数。只出现过几次的词可能显示为上千次，图表下半部分则被数值几乎相同的无关词占满。现在计数是准确的，仍属估算的条目会用 `≈` 标注。

- **活跃度图表的速率此前高了六倍**

  时间线及其峰值、均值都标注为「每分钟」，但实际统计的是每 10 秒一个区间，因此三个数字都约为真实速率的六倍；超长直播由于自动降低精度，误差更大。现在显示的是真实的每分钟速率。均值也改为按整场直播计算，而不是只统计有弹幕的时刻；安静时段会以零值绘制，而不是按前后速率连成直线。

- **录制中途重启后统计不再归零**

  如果录制过程中应用重启，该场次的弹幕统计会从零重新开始，并用更小的数字覆盖已保存的结果。现在会接着之前的进度继续累加。

- **场次页面显示更多信息**

  弹幕面板新增每分钟平均弹幕数；收到过礼物的直播还会显示总数中弹幕与礼物各占多少。

- **录制过程中即可查看弹幕统计**

  弹幕统计不再等到直播结束才出现。录制进行时，大约每分钟保存一次统计快照，会话页面的弹幕面板（总数、活跃度时间线、活跃用户、高频词）在直播还在进行时就会逐步填充。如果录制中途程序崩溃或主机重启，最多只丢失最后一分钟的统计，而不是整场。

- **超长直播的活跃度时间线覆盖全场**

  弹幕活跃度图表过去只保留最近六小时的完整数据，更长的直播会悄悄丢掉最早的数据点。现在达到上限时会把图表分辨率减半，因此 12 小时的录制也能从第一分钟画到最后一分钟，只是粒度更粗。

- **活跃用户榜可展开**

  会话页面的活跃用户卡片默认显示最活跃的 6 位，可以展开查看完整排名，展开后的列表支持滚动。排名人数可配置，默认 100 位。

- **中日文弹幕现在能切分成真正的词**

  高频词统计此前只按标点、符号和表情切分。中文和日文书写时不使用空格，因此没有标点的弹幕仍会被整句当成一个「词」，图表里满是整句而不是词。现在这两种语言的弹幕会经过真正的分词，并补充了通用词典缺失的常见直播用语，因此 `主播今天好厉害啊` 会计入 `主播`、`今天` 和 `厉害`。其他语言不受影响。

- **新增互动人数指标**

  会话弹幕面板现在会显示本场有多少不同用户发过言（内存有界的估算值，通常误差在 2% 以内），与弹幕总数并列展示。此版本之前录制的场次显示为「—」。

- **新增礼物排行**

  对于在弹幕流中上报礼物的平台（Bilibili、斗鱼、Bigo、SOOP 等），会话页面新增送礼排行与热门礼物两张图表，均按礼物件数而非消息条数统计。只有当场收到过礼物时才会显示。

- **移除 `danmu_sampling_config` 配置项**

  这个模板/主播配置项从未产生过任何效果，统计一直是逐条计数的。该字段已从 REST API（`/api/templates`）和数据库中移除；现有配置会自动清理，包含该字段的旧导出文件仍可正常导入。

## Web 界面

- **下载录像时直接写入磁盘**

  当 Web 界面连接的应用位于另一个地址时，下载录像以前会先把整个文件读入浏览器，长录像可能迟迟无法开始下载，甚至耗尽浏览器内存。现在下载会边接收边写入磁盘。桌面应用中录像本就在本机，按钮会直接在所在文件夹中显示它，而不再复制一份。

- **主题色块会跟随刚选择的主题**

  以前在主题页面切换预设或明暗模式后，色块和对应的颜色值仍显示上一个主题的颜色。现在它们会跟随你的选择更新，整页刷新后也会显示当前主题的颜色。

- **日志实时视图在日志量大时依然流畅**

  当日志级别调高、输出量很大时，实时日志页面可能出现卡顿或跟不上刷新。现在新日志会先汇集起来分批渲染，无论输出多快页面都保持流畅。实时视图的重连和登录续期处理也与其他页面一致。

- **保存设置时不再带上你没有选择的值**

  以前保存带有抖音专属覆盖设置的主播时，会把你没有设置的选项一并填上，导致这些选项不再跟随平台设置；现在这些选项会保持未设置状态，继续沿用上层配置。抖音平台设置页也会显示各选项的默认行为，而不再把未改动的选项显示为关闭。

- **退出登录后会彻底清除当前账号**

  以前退出登录后，用浏览器的后退键仍可能看到已登录页面，同一标签页中下一个登录的人也可能在短时间内被当成上一个账号。现在退出登录会立即清除账号信息，只能通过登录页重新进入。同样，当管理员要求你在使用过程中修改密码时，该要求现在会立即生效，而不再有短暂的延迟。

- **下载和上传进度不再时不时消失又出现**

  以前进度卡片会每隔一段时间突然消失，过一会儿又重新出现，而传输本身其实一切正常。这是后台例行续期登录状态造成的中断；现在实时连接会在续期期间保持不断，进度会一直显示在页面上。

- **页面打开更快，切到后台后更安静**

  以前每次切换页面都会重复同样的登录检查，并重新拉取刚刚获取过的列表。现在短时间内会直接复用已获取的内容，返回某个页面时可立即显示；原先每五秒刷新一次的几个概览页面改为每十秒刷新一次。标签页切到后台时，页面也会暂停自动刷新，切回来后再继续。

- **运行中任务的日志保持实时，且不会越往回翻越卡**

  以前查看运行中任务的日志时，每分钟都会把你往回翻过的日志重新读取多次，任务越长页面就越卡。现在只读取最新的部分，已经翻过的旧日志保持原样；任务结束后日志仍会补全到最后一行。

- **屏幕阅读器和键盘可以操作所有控件**

  只显示图标的按钮（菜单和侧边栏按钮、返回箭头、移除和复制按钮、播放器的设置和移除按钮，以及管道图的缩放控件）此前会被读成没有名称的按钮，屏幕阅读器无法说明它们的用途。现在它们都有了可朗读的名称。时间过滤器中的星期和小时选择器，以及恢复备份时的合并/替换选项，此前只能用鼠标操作。现在可用 Tab 键定位并通过键盘操作。星期和小时按钮用空格键，合并/替换选项用方向键，并会朗读当前选中的选项。

- **清空的设置框现在会保持为空**

  以前清空一个数字（超时时间、重试次数、图片宽度等）会留下一个无法保存的值，保存时会提示该值不是数字。斗鱼的首选 CDN 更是完全无法清空。删掉后会立刻填回原来的值。现在清空输入框会让该设置恢复为默认值，输入框保持为空，并在框内提示实际将会使用的值。只接受整数的设置项现在会直接在表单里给出提示，而不再让小数一路传到后面才失败。

- **编辑设置列表时不会再跳到别的行**

  以前删除一行自定义 Webhook 请求头、元数据标签或流参数时，剩余各行的内容会移到相邻行上，光标也随之移动。新增两个空白自定义标签时，它们还会立刻合并成一个。现在每一行都会保留你在其中输入的内容，空白行互不影响，标签在你为它命名后才会被保存。

- **原始 JSON 编辑器不再改写你输入的内容**

  在平台选项的 JSON 视图中，以前每敲一个字符都会把整段内容重新排版并把光标移到末尾，导致根本无法输入紧凑格式的 JSON。现在文本会保持你输入的样子，内容不完整时只会给出提示而不会被丢弃，载入配置或取消时编辑器仍会同步刷新。

- **通知订阅在切换窗口后不会丢失**

  以前为通知渠道勾选事件后，切换到其他窗口再切回来，所有勾选都会被丢弃并还原成上次保存的内容。现在你的选择会一直保留到保存或关闭对话框为止；直接点击复选框也能正常切换，而不再只能点击它周围的整行。

- **哔哩哔哩扫码登录会在二维码过期后停止**

  以前登录对话框在二维码过期后仍会每两秒向服务端查询一次，而且只要在设置页面的其他地方打字，就会额外发出一次请求。现在二维码一旦过期就会停止查询，等待你重新获取新的二维码。

- **勾选的条目不会再被带到其他页面**

  在录像和主播列表中，你勾选过的条目在搜索、切换筛选条件或翻页之后依然处于选中状态，即使它们已经不在屏幕上；此时执行删除或批量操作，这些条目也会被一并处理。现在只要列表显示的内容发生变化，勾选就会被清空，操作只会作用于你看得见的条目。

- **下载录像会立即开始**

  以前从场次页面保存录像时，浏览器会先把整个文件读进内存，然后才弹出保存提示。很长一段时间内看不到任何反应，遇到大文件甚至可能导致页面崩溃。如果 Web 界面与录制程序位于同一地址（常见的部署方式），现在下载会直接写入磁盘，点击后立刻开始；若两者地址不同，以及在桌面端，文件仍会先在浏览器中准备，期间会显示进度提示。播放器窗口的标题也已汉化。

- **一项无法读取的设置不会再让平台和模板页面变成空白**

  以前只要某个平台或模板保存的设置无法读取（例如由旧版本写入或被手工改动过），整个列表就无法加载。现在只会跳过那一项无法读取的设置，其余设置和其他条目都会正常加载。

- **没有弹幕统计的录像会直接说明情况**

  以前打开没有弹幕统计的录像（未开启弹幕录制，或录制刚刚开始）时，页面会显示「加载弹幕统计失败。」并附带重试按钮。现在会直接说明该场次没有弹幕统计。

- **无法打开的处理管道会说明原因**

  以前打开一个已不存在的处理管道，或在服务端连不上时打开管道，页面会一直停留在加载占位符上。现在页面会说明出了什么问题，并提供返回入口。

- **退出登录后重新登录如同全新开始**

  以前退出登录后，下一个人在同一标签页登录时，仍会短暂看到上一个账号的主播、录像和传输记录；而在未登录状态下点开应用内的链接，登录后也会被直接带回仪表盘，丢失你原本想去的页面。现在退出登录会清空上一次会话的全部内容，登录后也会回到你最初打开的那个页面，并保留其中的搜索词和筛选条件。

- **仪表盘的处理卡片会跟上取消操作**

  以前取消处理管道后，处理任务页面的计数会更新，但仪表盘上的处理卡片仍显示旧数字，直到下一次自动刷新。现在两者会同步更新。

- **通知与预设卡片重新显示配色**

  以前每张通知渠道卡片和处理预设卡片顶部图标背后的圆角色块失去了配色，只剩一片素底。现在这些色块会重新按渠道类型或处理步骤的种类着色。Discord 是靛蓝、邮件是蓝色、上传是绿色，等等。

- **配置编辑器输入时响应更快**

  以前编辑模板、平台或主播时，每输入一个字都会重绘整个表单，字段较多的页面会明显卡顿，打开管道编辑器时尤其明显。现在改动只会刷新页面上显示它的那一部分。**备份与恢复**中的导入结果、时间过滤器中的 24 小时时间条也不会再因为无关的改动而重新生成；正在录制页面上的实时数字也能平滑地滚动到位，不会中途停住。

- **浏览器控制台不再输出工作流配置和日志流地址**

  以前保存管道工作流时，会把完整的步骤配置打印到浏览器开发者控制台，其中可能包含上传凭据；打开日志查看器时也会打印它所连接的地址，而该地址中带有你的访问令牌。现在两者都不会再打印。

- **界面中最后一些未汉化的角落现在会跟随所选语言**

  以前无论选择哪种语言，界面上仍有一些地方停留在英文，包括主题导入对话框、弹幕查看器的筛选按钮和底栏、视频播放器的标题与错误提示、播放器表单中的 Cookie 字段、录像卡片上的状态标签、侧边栏底部的版本信息、录像分割时显示的对比表格，以及几个供读屏软件使用的按钮说明。诸如「12 messages」「3 Segments (7 Files)」「5 selected」这类数量文字也是由分散的词拼接而成，无法用中文自然表达。现在这些都会按所选语言显示，新建处理任务表单上的校验提示同样已汉化。

- **日期、时间和时长跟随所选语言**

  通知、主播卡片和系统健康页面上的「5 minutes ago」，以及录像页和日志页的日期区间，以前始终以英文和英文日期格式显示。现在它们会跟随所选语言，场次时长的单位也会用中文显示。尚未结束的场次现在显示为「进行中」，不再是拼写有误的「In active」。

- **链接有问题时不再让整个列表页变成报错**

  录像、主播、平台、模板、处理任务、工作流、预设、媒体文件、通知事件列表和播放器都会把你的搜索词、筛选条件和页码记在网址里。以前只要其中任何一项无法被页面识别（比如手动改过的网址、被截断的链接，或是更新后筛选条件取值发生变化的旧链接），整个页面就会变成「出错了！」以及一大段技术细节。现在无法识别的取值会被直接忽略，网址里其余部分照常生效。一个既带搜索词又带无效页码的链接，现在会正常执行搜索并从第一页开始显示。

- **媒体文件页面现在看得清了**

  以前**媒体文件**页面上的卡片不论内容是什么都变成同一个样子，较长的录像文件名只能显示两三个字。现在每个文件都会先用带颜色的图标标明它到底是什么。录像、音频、缩略图还是弹幕文件，随后单独一行显示完整文件名，下面再显示它所在的目录。文件大小和所属场次放在卡片底部。仍然放不下的文件名会以省略号结尾，鼠标悬停即可看到完整内容。

- **媒体文件类型已汉化，并可筛选整个文件库**

  列表上方的类型按钮以前直接显示内部名称 `VIDEO`、`THUMBNAIL` 和 `DANMU_XML`，在任何语言下都不翻译；而且这些按钮只根据你当前所在的那一页生成，因此翻页时按钮会变，点击后也只能筛选当前页。现在它们会按你的语言显示为**视频**、**音频**、**缩略图**和**弹幕**，并各自标注整个文件库中该类型的文件数量；点击后筛选的是全部文件，而不只是当前页。搜索框旁边的文件数量和总大小也会随所选类型和搜索条件变化，不再只是把当前屏幕上的内容加起来。

- **可以直接查看磁盘剩余空间**

  以前系统健康页面对存储只显示「健康」，在空间真正不足之前无法判断该不该清理。现在新增了**存储**板块，会为每一块写入录像的磁盘显示剩余空间、已用比例，以及一条随占用升高由绿转黄再转红的进度条。磁盘来自你配置的输出目录，包括主播、模板和平台级别的单独设置，因此第二块硬盘同样会被统计；位于同一块磁盘上的目录会合并显示。仪表盘的**磁盘**卡片也改为直接显示最满的那块磁盘的剩余空间，而不再只是一个状态词。

- **场次时间线不再隐藏能够识别的事件**

  以前只要某条生命周期记录的详细信息缺失或无法读取，它就会被显示为无法识别的事件。现在，能够识别的记录（场次开始或结束）会正常显示其名称，并注明详细信息不可用。

- **侧边栏新增用户菜单**

  用户账户相关操作已整合至侧边栏底部的用户菜单浮层中。现在可以在任意页面一键前往 API 密钥管理、账户设置、修改密码或退出登录。

- **工作流步骤不再显示错误的预设**

  打开使用预设的步骤时，可能会显示另一个预设的设置；此时点击**分离并编辑**，该步骤就会被替换成所显示的那个预设。上传或转码步骤可能因此悄悄变成删除步骤。现在步骤始终显示它所指定的预设；如果该预设已被重命名或删除，会直接给出提示，而不再退回到无关的预设。

- **服务端短暂异常不会再把你踢下线**

  以前只要在浏览器续期登录状态的那一刻服务端正在重启、暂时连不上或返回了错误，你就会被退回登录页并需要重新输入密码；重启或升级期间只要开着页面的人都会遇到这种情况。现在，除非登录状态确实已经过期，其他任何原因导致的续期失败都不会让你退出登录，稍后会自动重试。

- **登录过期后会自动回到登录页**

  以前如果登录状态在页面打开期间过期，页面会停在原地。所有操作都会失败，只有手动刷新才能回到登录页。现在应用会自行察觉过期并带你回到登录页，重新登录后会回到之前所在的页面，并保留其中的筛选条件和搜索词。

## 安全

- **凭据刷新保存完整的替换结果**

  Cookie 与所提供的令牌原子保存；JSON 无效或后续写入失败时保留原值。不存在或正在退出清理的配置拒绝刷新，未提供的令牌保持原值。详见[凭据刷新存储](../operations/security.md#凭据刷新存储)。

- **Web 服务端会校验转发的标识**

  Web 界面代你发起的请求，现在会拒绝空白、超长或非文本的条目标识，不再直接转发给应用。名称、搜索词等含有斜杠、问号、重音符号或空格的值会被正确转义，请求始终指向本应访问的条目。日常使用不受影响。

- **百度网盘登录凭据不再出现在进程参数中**

  手动及自动 BaiduPCS-Go 登录现在使用私有标准输入与配置暂存。仅在临时目录中禁用命令历史，已有历史、其他设置和账号保持不变。成功登录的账号更新会原子提交，失败时保留原配置；请求取消或超时会先清理受约束的子进程，再释放账号访问锁。兼容程序与存储边界详见[百度网盘登录](../concepts/pipeline.md#百度网盘-baidupcs)。

- **通知诊断一致隐藏凭据**

  渠道配置的 Debug 输出会隐藏令牌、密码、可能包含凭据的 URL、认证请求头及私人目标地址，包括嵌套服务配置。Web Push 诊断也会隐藏 VAPID 私钥、缓存令牌和订阅凭据。序列化与发送继续使用原有配置值。

- **成功登录不会清除其他失败的登录尝试**

  同时发起登录请求时，一个成功请求可能清除登录限制中另一个请求的失败记录。现在释放成功尝试所占的额度时，会保留来自同一地址的其他尝试。

- **Cookie、令牌与密码不再写入日志**

  开始录制、保存平台、模板或主播配置，以及后台自动检查平台 Cookie 是否过期的过程，此前都会把凭据本身写进日志文件、实时日志视图和浏览器控制台。任何能读到日志文件、日志导出或容器日志的人，都能从中找出平台账号的 Cookie、刷新令牌和账号密码。现在日志只记录改动了哪些配置项，不再记录它们的值。已有的日志文件不会被自动清理，如果你此前把日志分享给过别人，请更换其中出现过的 Cookie 和密码。

## 部署

- **通过 HTTPS 反向代理访问时，登录 Cookie 会自动受到保护**

  当 Web 界面通过终止 HTTPS 的反向代理对外发布时，保存登录状态的 Cookie 以前只有在手动设置 `COOKIE_SECURE=true` 之后才会被标记为仅 HTTPS，否则浏览器在普通 HTTP 请求中也会发送它。现在反向代理报告的协议能够原样传递给应用，Cookie 会自动带上仅 HTTPS 标记。家庭或办公网络内的纯 HTTP 部署不受影响，`COOKIE_SECURE` 也仍然可以在两个方向上覆盖自动判断。如果生产环境仍在通过普通 HTTP 访问，会记录一条提示警告（仅记录一次）。

- **可选的容器自动更新**

  Docker Compose 文件新增了可选的 `watchtower` 服务（`docker compose --profile autoupdate up -d`），可自动拉取新镜像并重启容器，但只在系统空闲时进行。新增的免认证 `GET /api/health/idle` 端点会报告当前是否有录制、排队录制或执行中的管道任务（上传、remux、弹幕转换等）；只要处于忙碌状态，更新就会推迟到下一次检查，因此重启不会打断任何录制或上传。自动更新要求使用可变镜像标签（`VERSION=latest`）。详见[升级与回滚](../operations/upgrading.md#自动更新watchtower)。

## 安装

- **自适应语言的 `install.sh` 安装脚本**

  `install.sh` 引导脚本现在会自动根据系统语言（或 `SREC_LANG` 环境变量）分发至对应的中文或英文交互式安装流程。脚本在执行前会校验下载内容的合法性，避免在网络代理或认证门户劫持时意外执行错误页面，并在无法安全生成随机密钥时主动终止安装。

- **从源码构建现在需要 Node.js 26**

  Web 界面与文档站点现已使用 Node.js 26 构建。如果你从源码构建 rust-srec，请在运行前端之前升级 Node。仓库现已提供 `.nvmrc`，版本管理器会自动选择正确的版本。Docker 与预编译二进制安装方式不受影响。

- **仓库自带的 systemd 服务文件可以正常启动录制程序**

  用仓库里的 `rust-srec.service` 把 rust-srec 装成系统服务后，服务无法启动。它会立刻因权限错误退出，根本没能连上数据库，而且需要的目录还得自己先手动创建。现在该文件会把日志写入 `/var/log/rust-srec`，由 systemd 在每次启动时创建并接管 `/var/lib/rust-srec` 与 `/var/log/rust-srec`，并从 `/etc/rust-srec/rust-srec.env` 读取 `JWT_SECRET` 等机密信息。停止服务时也会留出足够的时间让正在进行的录像保存完毕；原先固定的内存与 CPU 上限改为可选，不会再在不合适的机器上把录像中途截断；文件开头还列出了安装所需的命令。首次启动后，请在 Web 界面里设置录制目录。内置的默认值指向 Docker 镜像内部的路径，因此以系统服务方式运行时，不改就录不下任何内容。以该服务方式录制的文件仅 `rust-srec` 账号及其用户组可读，如果还有其他账号需要访问（文件服务器、媒体库扫描等），请把它加入该用户组。Docker 安装方式不受影响。

## 桌面端

- **启动过程中退出不再残留录制程序**

  如果在桌面端尚未启动完成时退出应用，而此时已有直播开始录制，录制程序可能会残留在后台。现在，如果录制服务已经开始启动，应用会先让它们完成启动，妥善停止所有录制，然后再退出。在此期间再次点击退出也不会打断这一过程。

- **在 macOS 菜单栏或 Dock 中退出时会先让录像收尾**

  在 Mac 上，按 Cmd-Q、在应用菜单中选择「退出」或从 Dock 退出，此前会立即结束应用，跳过托盘「退出」所做的收尾处理，正在进行的录像可能被截断，或者录制程序残留在后台。现在这些方式都会先停止录像，最长等待一分钟。从 Dock 退出或注销时，窗口在此期间会暂时无响应。

- **Linux 和 macOS 上的后台开销更低**

  桌面端此前每秒多次检查窗口状态，以便把最小化的窗口收进托盘。现在改为在窗口被最小化时直接响应，不操作窗口时不再做任何检查。最小化仍会把窗口收进托盘。

- **关闭应用时会先让录像收尾**

  在录制过程中退出桌面端，可能会让录制程序残留在后台，或者让文件被截断。现在应用会先等录像保存完毕再退出，最长等待一分钟。

- **同一个录制数据库只允许一个实例使用**

  桌面端和单独运行的 rust-srec 服务端此前可能同时打开同一个数据库，彼此都不知情，从而把同一批主播重复录制一遍。现在后启动的一方会直接退出。

- **修复首次启动时的 SQLite 锁定问题**

  桌面端现在会在打开读写连接池之前，通过专用的引导连接预先确立 SQLite WAL 模式。此前，两个连接池的并发初始化在初次创建数据库文件时可能会因竞争专属锁而触发瞬态的 `SQLITE_BUSY` 错误，因为 SQLite 切换日志模式所需的专属锁无法通过 busy timeout 等待。连接池在后续扩容新连接时也不会再重复执行该日志模式指令。

- **启动故障恢复与安全模式界面**

  当桌面端遇到无法自动恢复的启动错误（如数据库被占用锁定、权限不足、磁盘空间不足或数据库损坏）时，现在会展示专用的安全模式恢复界面，而不会直接静默崩溃或卡死。该界面清晰标注故障阶段与错误类型，提供针对性的排查建议，支持一键打开数据目录与日志文件夹，并可一键复制完整的诊断日志。
