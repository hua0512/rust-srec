# 录制时间安排

每周固定时段可使用时间过滤器，周期规则可使用 Cron 过滤器。为主播配置过滤器，选择时区，并核对过滤器卡片显示的有效时间安排。

## 示例：晚间录制

1. 为主播添加时间过滤器。
2. 选择星期和录制区间，例如 20:00–23:00。
3. 选择**服务器本地**或输入 `Europe/Madrid` 等 IANA 时区。
4. 保存后检查卡片上显示的时区。

跨午夜录制可使用 22:00–02:00 等区间，归属于开始时的星期。时间安排只决定是否允许录制；主播还需处于直播状态，且有可用录制名额。

## 过滤器时区与边界 {#过滤器时区与边界}

后端 `TIME_BASED` 和 `CRON` 过滤器 JSON 支持可选的 IANA `timezone`，例如
`"Europe/Madrid"`；也可使用 `"local"` 跟随后端系统时区及其夏令时规则。匹配、下一次
开始和结束统一使用该时区。跨夜区间归属于开始
时的星期；时钟重复的小时内，开始使用较早时刻，结束使用较晚时刻，重叠或相接的
区间保持连续匹配。不存在的本地边界会向后移动到三小时内首个有效分钟；跳过时间
更长的日期窗口会被省略。

两种规则省略时区或设为 null 时均使用 UTC。升级会将已有 TimeBased 规则中省略或
为 null 的时区写为显式 `"local"`，保留原有行为；显式 IANA 时区和 Cron 规则保持
原意。两种过滤器表单都可选择 UTC、**服务器本地**，或输入 IANA 时区名称。
服务器本地指后端服务器的系统时区，可能与浏览器所在时区不同。过滤器卡片会在时间
安排旁显示实际使用的时区。编辑时保留已存储时区；清空时区控件会显式选择 UTC。
新建规则及切换规则类型也默认使用 UTC。切换时区时保留已输入的钟表时间，改为在
新时区内解释这些时间。

对于 API 客户端，同类型 TimeBased 更新省略时区成员时会保留已存储值；显式发送
null 或 `"UTC"` 可切换到 UTC。替换 Cron 配置时省略时区则使用 UTC。

备份格式 `0.1.8` 会为两种规则导出显式时区。导入 `0.1.7` 及更早格式时，TimeBased
规则的省略时区保留本地时间行为；新格式省略时区则表示 UTC。`"local"` 与旧版本地
规则一样，继续跟随目标服务器的系统时区。未知 JSON 成员保持不变。

Cron 按分钟匹配，包括含秒的
表达式，结束扫描仍以八天为上限。
